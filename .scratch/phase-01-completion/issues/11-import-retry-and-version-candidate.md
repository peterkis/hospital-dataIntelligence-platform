# 11 — 原批次幂等重试与新批次版本候选

**What to build:** 让原批次在故障或引用条件修复后安全重试并跳过成功行，同时让新批次中的已有业务键进入显式版本变更流程。

**Blocked by:** 03 — 收费项目版本、双时态与差异查询; 10 — 收费项目CSV与REST批量导入.

**Status:** ready-for-agent

- [ ] 原批次重试复用冻结输入和批次身份，已经成功的行不重复应用且身份、版本和审计不改变。
- [ ] 失败行可以在引用数据或技术条件恢复后重新求值，每次尝试只追加并保留旧错误证据。
- [ ] 输入字节、规范化内容或行集合发生变化时拒绝复用原批次，必须创建新批次。
- [ ] 进程在任意行边界崩溃后可以从持久化状态恢复，不丢失成功行或重复创建版本。
- [ ] 新批次遇到已存在业务键时创建新草稿版本候选，不忽略、覆盖或直接发布现有记录。
- [ ] UI显示已跳过成功行、重新处理行和新版本候选；生成客户端和故障测试证明幂等性。
