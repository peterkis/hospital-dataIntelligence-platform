# 16 — 发布事务逐写点原子故障矩阵

**What to build:** 对完整领域发布链逐个持久化边界注入可控故障，证明领域版本、审批、发布、快照、兼容预检、投递、审计和Outbox全部提交或全部回滚。

**Blocked by:** 08 — 价表高风险与院区差异价审批; 14 — 补偿发布与暂停恢复; 15 — 审计查询、哈希验证与显式顺序.

**Status:** ready-for-agent

- [ ] 测试故障点使用封闭枚举并只能在测试配置启用，生产启动时发现故障配置必须失败。
- [ ] 对领域候选确认、审批决定、发布包络、成员、快照字节、兼容预检、独立投递、审计和Outbox写入逐点失败。
- [ ] 每个提交前故障均留下零半发布、零孤立快照、零Outbox和零检查点推进。
- [ ] 成功路径仍在单一数据库事务提交，事务内不存在消费者网络调用。
- [ ] 失败和成功运行使用生成客户端或受控测试入口触发，并输出机器可读写点结果。
- [ ] 故障矩阵进入不可覆盖证据，既有发布、双摘要和历史消费者状态不被测试重写。
