# 14 — 补偿发布与暂停恢复

**What to build:** 让Owner通过审批后的新版本、修正版或补偿发布恢复未来适用性，并证明旧版本不能原地恢复且历史解析不被改写。

**Blocked by:** 03 — 收费项目版本、双时态与差异查询; 04 — 价表草稿、完整快照与计划发布; 07 — 普通内容变更的版本化审批; 13 — 紧急单人暂停与影响事项.

**Status:** claimed

- [ ] 平台不存在把旧暂停版本直接切回活动状态的业务命令、UI动作或数据库业务权限。
- [ ] 恢复请求创建新的领域候选和审批请求，冻结纠正理由、来源发布及取代/补偿关系。
- [ ] 审批后形成新发布、新快照、新事件和新审计，不覆盖旧发布或暂停事件。
- [ ] 新业务时点解析可以使用恢复发布，暂停期间和更早记录时点仍返回原历史结果。
- [ ] 失败的补偿发布全量回滚并保持暂停有效，影响事项只有在闭环证据完成后才能关闭。
- [ ] REST、界面、双时态历史和仿真消费共同证明补偿发布而非原地回滚。
