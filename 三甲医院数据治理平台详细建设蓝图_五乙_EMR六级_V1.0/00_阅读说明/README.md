# 三甲医院数据治理平台详细建设蓝图（互联互通五级乙等 + 电子病历六级）

**版本：** V1.0  
**生成日期：** 2026-07-15  
**适用对象：** 大型三级甲等综合医院、多院区医院、医院集团/医联体  
**建设定位：** 医院级数据资产治理、临床数据中心、标准术语、主数据、数据质量、互操作服务、临床闭环、知识与决策支持的一体化工程。

## 1. 文件包使用顺序

1. 首先阅读 `01_总体设计/三甲医院数据治理平台详细建设蓝图.docx` 或同名 PDF，明确目标架构、建设边界、模块、路线、组织和验收方法。
2. 使用 `02_评测映射与验收/五乙_EMR六级_能力交付物证据矩阵.xlsx` 建立逐项差距、责任、状态和证据台账。
3. 使用 `03_数据域与数据模型/医院数据域_MDM_CDR_逻辑物理模型.xlsx` 和 `postgresql_核心表DDL.sql` 进入模型评审和技术设计。
4. 使用 `04_接口与数据服务/openapi_医院数据治理服务.yaml`、FHIR 映射表和事件示例开展接口联调。
5. 使用 `05_实施路线与项目管理/实施WBS_RACI_里程碑_风险_验收.xlsx` 管理项目、模拟测评和上线。
6. 使用 `06_治理制度与可编辑模板` 固化制度、流程、申请、变更、质量和证据管理。
7. `07_附件融合` 保留原始附件并给出规范化后的 121 项治理清单。

## 2. 交付范围摘要

- 数据域：15 个。
- 平台模块：19 个。
- 核心物理表：58 张，字段：931 个。
- 互联互通五乙工程映射：41 项。
- 电子病历六级工作角色映射：10 类。
- 临床闭环场景：15 个。
- API 契约：18 个，另含事件主题与 FHIR 映射。
- 实施 WBS：139 项。

## 3. 使用边界和重要声明

- 本文件包是一套**可落地的总体设计、详细设计和项目管理基线**，不是对正式测评结果的保证。
- 互联互通按《国家医疗健康信息医院信息互联互通标准化成熟度测评方案（2020年版）》进行工程拆解；如主管部门发布新版，以申报年度正式文件、通知和测评细则为准。
- 电子病历五级/六级按“统一数据管理、中级决策支持”以及“全流程医疗数据闭环管理、高级医疗决策支持”的建设主线进行工程拆解；具体功能点、必达项和现场评价规则以申报年度官方细则为准。
- SQL、OpenAPI 和数据模型是参考实现，需结合医院数据库、中间件、源系统版本、国产化环境和安全要求评审后使用。
- 医疗健康信息属于敏感个人信息；生产落地必须完成分类分级、最小权限、用途绑定、脱敏、导出审批、审计和影响评估。

## 4. 建议项目治理方式

以“数据域 Owner + 数据管家 + 技术 Owner + 安全审计 + 评测证据专员”五类角色联合负责。评级条款、数据资产、接口、质量规则、闭环流程和证据应使用同一套唯一编号贯通，不得临近申报时临时拼接。
