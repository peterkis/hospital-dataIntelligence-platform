# 备份与恢复运行手册

## 1. 目标

采用3-2-1-1-0原则：至少3份数据、2种介质、1份异地、1份不可变或离线、恢复校验0错误。备份成功不等于可恢复，验收以隔离环境恢复证据为准。

## 2. 备份对象与频率

| 对象 | 策略 | 在线保留 | 异地/不可变 |
|---|---|---:|---|
| PostgreSQL | 全量周备 + 每日增量 + 连续WAL/PITR | 35天 | 12个月关键月末 + WORM |
| Ceph/Iceberg | Bucket版本化、快照、RGW Multisite | 30-90天 | 异地对象与季度封存 |
| Kafka | 关键事件落湖、MirrorMaker2；Topic配置备份 | 按Topic | 异地关键事件与配置 |
| OpenSearch | 每日增量快照、每周全量验证 | 30天 | 异地快照仓库 |
| K8s/配置 | Git、Helm Values、CRD、Secrets元数据 | 永久版本 | 异地Git + KMS密钥备份 |
| OpenMetadata/Keycloak | 外置数据库PITR + 配置导出 | 35天 | 异地数据库副本 |
| 证书/KMS/HSM | 双人授权密钥备份与恢复流程 | 按密钥周期 | 离线/异地保险库 |

## 3. 日常检查

1. 检查备份任务、WAL连续性、快照仓库、对象复制、密钥备份和容量。
2. 每日抽取随机文件/对象做checksum校验。
3. 每周恢复一个小型数据库或Schema到隔离环境。
4. 每月检查恢复文档中的账号、DNS、证书、白名单和责任人是否仍有效。
5. 每季度执行全量恢复演练；对患者合并、标准发布和误删除做业务级回滚。

## 4. PostgreSQL恢复步骤

1. 启动事件指挥，冻结写入或将应用切至只读/降级模式。
2. 确定目标恢复时间点，保存当前损坏现场和审计证据。
3. 在隔离环境恢复基线全备，回放WAL至目标时间。
4. 执行一致性检查：金记录、xref、版本、审批、Outbox、审计数量和checksum。
5. 由业务Owner验证患者/组织/药品等关键对象。
6. 采用新实例接管，禁止直接覆盖原损坏实例；完成DNS/连接池切换。
7. 记录RTO/RPO、数据差异、操作人、审批和后续整改。

## 5. 恢复验收

- 可查询最新与历史版本；患者合并与回滚链完整。
- Outbox未发布事件可继续发布，已发布事件不会重复产生副作用。
- 审计连续且不可由应用管理员修改。
- 证书、密钥、OIDC、网关和下游消费者均通过。
- 实际RTO/RPO不超过约定目标；任何偏差形成整改工单。
