# 大型三甲医院数据治理平台详细设计交付包

设计基线：2026-07-15

## 交付物

- `01_大型三甲医院数据治理平台详细技术架构设计说明书.docx/.pdf`：主说明书；
- `02_建设失败案例与复盘手册.docx/.pdf`：公开案例、综合反模式、Go/No-Go与复盘模板；
- `03_详细设计附录台账.xlsx`：容量假设、服务器规划、选型、RTO/RPO、数据库、API、Topic、质量规则、RACI、失败案例、验收和源系统接入模板；
- `04_架构图`：8张PNG/SVG架构图；
- `05_数据库设计`：核心DDL、索引分区、安全/RLS/Outbox和数据库说明；
- `06_接口设计`：OpenAPI、AsyncAPI和同步规范；
- `07_部署与运维`：K8s参考、监控告警、备份恢复、灾备演练、版本许可复核；
- `08_实施与验收`：实施计划、验收清单、切换回退；
- `09_参考资料`：权威资料、附件适配和预览。

## 规模假设

默认按3院区、3500开放床位、180套源系统、年门急诊900万人次、结构化日增180GB、审计日志日增120GB、CDC短时峰值3万条/秒、API 3000 QPS、5年规划。工作簿黄色单元格可编辑并自动重算。

- 核心治理、结构化、日志和基础湖仓建议原始容量约0.8PB；
- 若另纳入大规模AI影像/对象派生数据，参考原始容量约2.0PB；
- 原始DICOM像素的长期PACS归档未默认计入，必须单独盘点。

## 使用边界

该方案可直接作为立项、招标技术需求、PoC、详细设计和验收底稿，但不是未经校准即可采购的固定BOM。正式采购前必须用真实系统数量、日增量、峰值、保留期、网络和源库性能进行PoC与压测；所有组件版本、许可证和供应链安全须重新核验。
