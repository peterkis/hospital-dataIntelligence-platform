# 上线切换与回退计划模板

## 1. 切换策略

优先采用影子运行、双查、双发、灰度消费，而非大爆炸替换。

1. **影子期**：MDM生成结果但不影响生产；与源系统和人工基准对账。
2. **双查期**：业务系统同时查询旧字典/新服务，记录差异，不改变业务决策。
3. **双发期**：MDM事件发送至测试消费者，验证幂等、顺序、延迟和补偿。
4. **灰度期**：按院区、科室、对象类型或下游系统逐步切换。
5. **主用期**：新平台成为统一发布口，旧入口转只读并按计划退役。

## 2. 上线前No-Go红线

- 存在未解释患者误合并、数据串档、药品停用未传播；
- 阻断级质量规则不能阻断；
- 接口无幂等、DLQ或补偿；
- 数据库/事件/业务回滚未演练；
- 性能、源库影响、安全、备份或灾备测试未通过；
- 域Owner和一线操作责任未明确。

## 3. 回退触发

- 患者安全事件或疑似串档；
- 关键接口5xx、超时、Lag超SLO并持续；
- 数据差异超过批准阈值；
- 源系统性能下降超阈值；
- 审计缺失、越权或敏感泄露；
- PostgreSQL/Kafka/Ceph出现不可控一致性风险。

## 4. 回退步骤

1. 宣布冻结窗口，停止新增变更/自动合并；
2. 网关将读流量切回旧服务或受控缓存；
3. 停止事件发布，保存Outbox、消费位点和DLQ；
4. 使用发布版本/rollback token恢复主数据和标准；
5. 向下游发布补偿事件并获取确认；
6. 对患者、组织、人员、药品做抽样和全量对账；
7. 记录审计、影响、患者安全复核与后续决策；
8. 完成根因整改和再次Go/No-Go评审后方可重启。

## 5. 切换记录

必须记录：版本、时间、操作人、审批人、变更单、系统范围、数据量、性能、异常、回退点、下游确认、最终结论。
