# 数据库设计说明

## 1. 设计模式

核心主数据采用“主实体表 + 标识表 + 来源交叉索引 + 关系表 + 双时态版本表”。主实体保存当前金记录；`xref`保存每套源系统原始主键；`entity_version`同时保存业务有效时间和平台事务时间，以支持历史追溯、影响分析和回滚。

## 2. 标识策略

- 内部主键：UUID/有序UUID，永不暴露业务语义。
- 企业可读编码：EMPI_NO、ORG_CODE、STAFF_MASTER_NO等，由专用编码服务生成。
- 源系统键：`source_system_code + source_record_key`唯一。
- 敏感自然标识：密文 + HMAC/哈希，禁止将身份证号、手机号明文用作主键、Topic Key或日志字段。
- 版本：实体版本不可覆盖；发布后产生`publication`和`rollback_token`。

## 3. 患者安全控制

患者身份解析只治理人口学与标识，不覆盖临床原始诊断、检验结果、报告正文。证件冲突、双胞胎、未成年人、无证件急诊、监护人代办、境外证件等必须进入分层规则；高风险合并采用四眼复核并保留合并前后快照。

## 4. 双时态与生命周期

科室改名、撤并、人员调岗、药品停用、床位调整等均使用`valid_from/valid_to`和`transaction_time`，不物理删除。历史事实按发生时有效版本解释；新业务只消费当前有效版本。

## 5. 分区与保留

审计、执行批次、接口流水、事件Outbox按月或按日分区；在线保留期与WORM归档分离。容量规划至少预留35%增长空间，磁盘达到70%-75%启动扩容，80%进入高等级告警。

## 6. 高可用

PostgreSQL建议Patroni 1主2备，本地关键事务同步复制，异地异步复制加PITR。必须配置fencing、防脑裂、连接池重连、WAL归档、备份校验与季度恢复演练。

## 7. 数据库验收

验收不仅检查DDL创建成功，还要验证：并发写、热点索引、故障切换、PITR、误合并回滚、密钥恢复、RLS、越权拒绝、审计完整性、分区创建与归档恢复。
