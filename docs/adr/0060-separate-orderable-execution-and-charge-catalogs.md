# 医嘱、执行服务与收费项目三目录分离

临床医嘱目录、执行服务目录和院内收费项目目录分别拥有稳定身份、不可变版本、Owner、权限和发布流程。临床医嘱回答“请求了什么”，执行服务回答“实际提供了什么”，收费项目回答“收取什么费用”；三者不得共用一个通用医疗项目身份，也不得在医嘱版本上保存单一收费项目外键。医嘱收费映射作为独立版本化治理对象，允许零对多及多对多关系，冻结源医嘱版本、可选执行服务版本、目标收费项目或收费组套版本、触发状态、数量规则、适用范围、资格条件、测试样例、审批和有效期。科室、执行方法和结果状态可以影响映射或资格，但不得改变院内价格。映射解析先生成不可变证据，再独立执行价格解析并保存价格证据。实际患者医嘱、执行记录、患者上下文和费用流水属于业务事实，不进入主数据。三个目录和映射规则分别发布；上游变化只触发影响事项和显式重审，不做跨对象原子发布或自动迁移。后续ADR-0061和ADR-0065已将相关合成目录和映射纳入邻接薄切，并量化为8个医嘱目录项目、6个执行服务和12条医嘱收费映射规则。
