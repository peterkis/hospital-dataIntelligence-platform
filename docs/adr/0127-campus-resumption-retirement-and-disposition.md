# 院区恢复、永久退出与处置结案分离

用户批准P1-07扩展0124的阶段边界。暂停仍阻断普通ACTIVATE，新增RESUME在同一稳定身份上显式审批并重新准入。永久退出保留身份与代码，不允许恢复或新运营声明。未来生效按业务时间表达，记录时间真实追加；旧未来安排不能重新激活暂停或退出节点。

永久退出是停止新增准入的事实，处置结案是独立证据结论。退出不级联关闭运营、任职或地点，原Owner分别结束源关系。依赖失效不阻断合法非扩张关闭；关闭也不恢复原关系。

影响报告固定连接当前Owner。尚未建设的业务单元、地点、任职和消费报告NOT_EVALUABLE，不能伪装成零依赖。手工处置证据只表示具名来源在明确合成范围的声明，不是自动集成验证。未知在途和实际未处置依赖阻断结案，候选绑定准确影响摘要，应用前重查。

本票不引入法人注销、人员或消费系统；真实下游集成待后票补验，局部实现完成不等于P1阶段或生产就绪。

未来退出生效前，完整期间在退出之前的合法维护或运营声明仍可准入；跨越退出边界的扩张阻断。退出实际生效后，新增或扩张不能借回填到过去绕过终态。影响报告分别表达退出期间内的历史受影响事实和当前仍有效/未来尚待结束的义务；退出后晚些时间合法关闭的历史区间不永久阻断结案。

## 恢复后的运营升级边界

暂停期间仍禁止通过 ACTIVATE 或开业计划绕过 RESUME。RESUME 沿用本票已有的来源核验规则，允许按独立审批结果恢复为 TRIAL_RUNNING 或 RUNNING，不强制新增试运行阶段。当显式 RESUME 选择试运行时，之后可用独立审批的普通 ACTIVATE 申请转正式运行；准入按申请的完整业务期间计算有效暂停区间，而非仅检查历史上是否出现过暂停。只有更新的运营状态事件可扣减暂停区间，资料 REVISE 不参与扣减。有限恢复结束后重新落入暂停的部分仍被阻断，退出限制不变。

0080 前向迁移同时修正最终 SQL 写入门禁和当前界面的 canActivate 投影，不覆盖 0079。运行与部署的同一校验和清单推进至 0080；0079 持久工作区必须先受控升级，不能使用新应用配旧门禁。隔离 GitHub CI 对已存在的暂停、恢复及失败激活请求执行 0079→0080 升级，并验证既有表数据、迁移账本、函数所有者及 ACL 保留。这不是生产或持久数据库升级证明。

0081 保留 0061 已建立的历史回填防护：只要存在暂停记录，ACTIVATE 的完整申请期间必须位于已显式批准的 RESUME 覆盖内，且不能与当前有效暂停区间相交。没有 RESUME 时，即使 ACTIVATE 回填到暂停之前且恰好在暂停起点结束，也仍被拒绝；开业计划仍允许不重叠的历史维护，且不改变运营状态。0080 保持原校验和，运行与部署门禁继续推进至 0081；升级逐步保留 0079、0080 的行、账本和函数权限。旧 P1-02 的 Owner 与独立签名 SQL 反例原样加入本轮 CI，不删除或放宽断言。
