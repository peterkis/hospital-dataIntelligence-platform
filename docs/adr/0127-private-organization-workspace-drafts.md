# 私有组织维护草稿与正式事实分离

按用户批准的 P1-06 计划，组织维护页面复用既有 Owner、公共审批和 Apply。编辑草稿允许字段不完整，仅原编辑人的 underlying identity 可恢复；读取及保存仍检查当前准确对象、配对与受限材料权限。草稿内容和未提交附件加密保存，保存不是发布。

完整提交在同根事务准备受控输入并追加提交关联。手工申请、整包候选、独立核验、批准和正式事实继续使用原有权威，不另建审批状态表。已有院区管家无需取得数据集全量写权限。内部元数据传输的复用按下文 0072 边界核验，其他情况仍需契约写权限。

页面身份切换清除受限内容并拒绝旧响应。列表窗口不限制准确深链接恢复；恢复原结果检查当前读取权限，不重算旧事实的扩张资格。所有读写通过生成客户端，服务端执行当前权限、版本、材料、来源意图与事务审计规则。

按用户后续确认，浏览器结构化时间输入与普通显示仅到秒，使用 yyyy-mm-dd hh24:mm:ss，用户编辑值补 .000000 送往后端。数据库已有微秒时间、同批精确观察时点和原始文件材料保持原精度。时间显示的简化不改变半开区间或证照日期当日零点失效规则。

## 0072：准确领域与同来源的手工维护传输

手工 ORG01、ORG02、ORG03 草稿只能提交到相同 dataset、CORE profile、已发布且模板为 `<domain>_MANUAL_CORE_V1` 的准确契约版本。来源版本必须与命令来源相同。前端过滤只提供可选项；Owner 在创建作业和登记附件前检查，SQL 入口重复领域、模板及读取权限检查。工作簿契约及其他数据集的非工作簿 CORE 契约都不能借作手工传输。

0071 的“必须沿用同一历史传输契约版本，否则要求目录写权限”规则不能覆盖工作簿生成的事实，因此由以下更精确的规则替代：对本人最新 EDITING 草稿，当前准确对象/配对的 READ、READ_RESTRICTED、WRITE 和治理归属均成立时，可将该对象已有不可变事实重新表达为**同一领域、同一来源版本**的手工元数据传输。工作簿来源从该输入修订的实际域 binding 取得，不使用整包根作业的 ORG01 传输契约冒充其他域来源；证照也通过真实主体关系追溯。

修订底稿仅选择当前可读取、显式发布、同域同来源版本的手工契约；没有匹配项时保持无传输绑定，不创建契约、不推断来源、不发布目录。来源命令、证据、标识以及旧事实和旧作业不改写。普通新建、切换到没有对象事实依据的新来源、文件接收和非草稿入口不获得该例外。数据库不新增任何权限授予记录；独立审批及领域 Apply 检查保持不变。

本修复使用新增迁移 `0072_workspace_domain_transports.sql`，不改写已安装的 0071 或其校验和。GitHub Actions 的临时 PostgreSQL 验证与原有收据约束的 WSL/持久部署验证分开记录；前者不是持久数据库升级、人工浏览器验收或生产准入证明。

## 证照历史版本的维护入口

当前资料视图保留全部已知证照历史，不删除撤销记录。具有维护权限时，只有非撤销版本可作为修订底稿；历史底稿的并发目标仍由既有 `prepareRevision` 绑定到当前证照 head，不把旧版本当成可覆盖的事实。

撤销入口仅对同一证照身份下最新且非撤销的版本开放。版本号按整数比较，不依赖字符串排序、返回顺序或业务生效时间；撤销版本与未来生效版本都参与 head 判断，不能过滤后把旧版本提升为最新。指定 B/R 的历史视图始终只读。

点击撤销时，通过已有生成客户端重新读取准确 LICENSE 上下文，核验身份、所属主体、当前 head 和当前维护权限，使用同次响应中的主体 head 构造草稿。版本或权限变化时提示重新读取，不静默撤销另一个版本，不使用旧缓存继续生成草稿。此入口约束不替代提交、审批及 Apply 时的后端版本和权限校验，也不需要新增迁移或扩大权限。

## 核验表单的证照依赖选择

登记核验的多选和许可范围核验的单选共用同一非撤销版本集合：仅 `revoked === false` 的断言可被选取，回调也从该集合构造准确引用，不能把旧草稿中已选的撤销记录夹带回申请。没有可选版本时明确显示空状态；旧草稿中已知的撤销引用显示警告，可由用户显式清除或重新选择，不在读取时自动修改草稿。

依赖选择与撤销动作不同，不要求依赖是最新版本，不按证照身份整体排除历史。同一证照存在后续撤销记录时，其非撤销旧版本仍保留为候选，能否支持所申请期间仍由 ORG01/ORG03 Owner 核验证照期限、覆盖、登记资格、材料和权限。完整历史接口及资料视图继续返回撤销记录，不通过删历史、放宽后端校验或改写迁移来消除错误入口。
