# 私有组织维护草稿与正式事实分离

按用户批准的 P1-06 计划，组织维护页面复用既有 Owner、公共审批和 Apply。编辑草稿允许字段不完整，仅原编辑人的 underlying identity 可恢复；读取及保存仍检查当前准确对象、配对与受限材料权限。草稿内容和未提交附件加密保存，保存不是发布。

完整提交在同根事务准备受控输入并追加提交关联。手工申请、整包候选、独立核验、批准和正式事实继续使用原有权威，不另建审批状态表。已有院区管家无需取得数据集全量写权限。内部元数据传输的复用按下文 0072 及 0073 边界核验，其他情况仍需契约写权限。

页面身份切换清除受限内容并拒绝旧响应。列表窗口不限制准确深链接恢复；恢复原结果检查当前读取权限，不重算旧事实的扩张资格。所有读写通过生成客户端，服务端执行当前权限、版本、材料、来源意图与事务审计规则。

按用户后续确认，浏览器结构化时间输入与普通显示仅到秒，使用 yyyy-mm-dd hh24:mm:ss，用户编辑值补 .000000 送往后端。数据库已有微秒时间、同批精确观察时点和原始文件材料保持原精度。时间显示的简化不改变半开区间或证照日期当日零点失效规则。

## 0072：准确领域与同来源的手工维护传输

手工 ORG01、ORG02、ORG03 草稿只能提交到相同 dataset、CORE profile、已发布且模板为 `<domain>_MANUAL_CORE_V1` 的准确契约版本。来源版本必须与命令来源相同。前端过滤只提供可选项；Owner 在创建作业和登记附件前检查，SQL 入口重复领域、模板及读取权限检查。工作簿契约及其他数据集的非工作簿 CORE 契约都不能借作手工传输。

0071 的“必须沿用同一历史传输契约版本，否则要求目录写权限”规则不能覆盖工作簿生成的事实，因此由以下更精确的规则替代：对本人最新 EDITING 草稿，当前准确对象/配对的 READ、READ_RESTRICTED、WRITE 和治理归属均成立时，可将该对象已有不可变事实重新表达为**同一领域、同一来源版本**的手工元数据传输。工作簿来源从该输入修订的实际域 binding 取得，不使用整包根作业的 ORG01 传输契约冒充其他域来源。ORG01 主体与证照的进一步隔离由下文 0073 规定，不再将同一主体全部证照来源合并为维护授权。

修订底稿仅选择当前可读取、显式发布、同域同来源版本的手工契约；没有匹配项时保持无传输绑定，不创建契约、不推断来源、不发布目录。来源命令、证据、标识以及旧事实和旧作业不改写。普通新建、切换到没有对象事实依据的新来源、文件接收和非草稿入口不获得该例外。数据库不新增任何权限授予记录；独立审批及领域 Apply 检查保持不变。

本修复使用新增迁移 `0072_workspace_domain_transports.sql`，不改写已安装的 0071 或其校验和。GitHub Actions 的临时 PostgreSQL 验证与原有收据约束的 WSL/持久部署验证分开记录；前者不是持久数据库升级、人工浏览器验收或生产准入证明。

## 证照历史版本的维护入口

当前资料视图保留全部已知证照历史，不删除撤销记录。具有维护权限时，只有非撤销版本可作为修订底稿；历史底稿的并发目标仍由既有 `prepareRevision` 绑定到当前证照 head，不把旧版本当成可覆盖的事实。

撤销入口仅对同一证照身份下最新且非撤销的版本开放。版本号按整数比较，不依赖字符串排序、返回顺序或业务生效时间；撤销版本与未来生效版本都参与 head 判断，不能过滤后把旧版本提升为最新。指定 B/R 的历史视图始终只读。

点击撤销时，通过已有生成客户端重新读取准确 LICENSE 上下文，核验身份、所属主体、当前 head 和当前维护权限，使用同次响应中的主体 head 构造草稿。版本或权限变化时提示重新读取，不静默撤销另一个版本，不使用旧缓存继续生成草稿。此入口约束不替代提交、审批及 Apply 时的后端版本和权限校验，也不需要新增迁移或扩大权限。

## 核验表单的证照依赖选择

登记核验的多选和许可范围核验的单选共用同一非撤销版本集合：仅 `revoked === false` 的断言可被选取，回调也从该集合构造准确引用，不能把旧草稿中已选的撤销记录夹带回申请。没有可选版本时明确显示空状态；旧草稿中已知的撤销引用显示警告，可由用户显式清除或重新选择，不在读取时自动修改草稿。

依赖选择与撤销动作不同，不要求依赖是最新版本，不按证照身份整体排除历史。同一证照存在后续撤销记录时，其非撤销旧版本仍保留为候选，能否支持所申请期间仍由 ORG01/ORG03 Owner 核验证照期限、覆盖、登记资格、材料和权限。完整历史接口及资料视图继续返回撤销记录，不通过删历史、放宽后端校验或改写迁移来消除错误入口。

## 工作簿行的来源、意图与证照目标

每行只提供其 dataset 对应的准确文件契约来源版本，同时匹配 contractId、contractVersionId、CORE、PUBLISHED 和 `<dataset>_BUNDLE_CORE_V1`。不合并三个领域的来源集合。旧草稿中的不匹配来源保留为明确不可用的显示项，须由用户重新选择；选择事件不能接受其他领域或未绑定版本。原始工作簿的 source_system_id、源单元格与字节不因选择器修复而改写，来源证据匹配仍由后端负责。

行意图切换为 CREATE 或清空时，在同一次清单修改中移除 target；依赖旧主体的证照修订目标及其修订意图同时清空。仅更换主体时移除旧主体的证照目标，不自动选择另一个证照。证照子操作切换为 CREATE 或清空时同样移除 license.target，保留命名空间、机关、证据、期限及其他已填写内容。新建主体不能选择修订既有证照。

ORG01 的证照修订选择器由已保存 license.target 的准确 id/version 驱动，保存恢复后仍显示同一目标。提供明确清除按钮，即使当前没有可读取选项，也允许在可编辑草稿中清除已有目标；只读状态不得通过回调修改。清除不自动选择最新版本、不修改后端事实。缺少目标的修订仍由既有编译器以 EXPLICIT_TARGET_REQUIRED 阻断，不放宽清单、权限、独立审批或 Apply 规则。

工作簿的证照修订清单直接绑定当前并发目标，不经过历史修订底稿转换，因此使用独立的 `CURRENT_REVISION` 选择用途，只展示每一证照的最新且非撤销版本。未来版本和撤销版本仍参与整数 head 判断；旧目标明确提示过期并允许重新选择或清除，不静默替换。登记核验及范围核验保持 `DEPENDENCY` 语义，历史非撤销版本仍可作为期间依据。每个证照选择器使用独立的单选组名，避免多行互相取消界面选择而保留旧清单。

## 编辑草稿的端点与上传边界

无既有修订目标的 ORG03 `ESTABLISH`、`VERIFY_SCOPE` 在未保存或已保存的 EDITING 阶段都能补齐、更正主体和院区。仅保存草稿不锁定端点；忙碌、已提交、已放弃、明确修订目标及修订/关闭命令仍锁定。更换主体时清除属于旧主体的证照依据；建立关系时更换任一端点清除旧配对的范围依据，保留来源、材料和其他独立字段。清除和重新选择是显式编辑，不是权限授予；能力查询、保存、提交和 Apply 继续按新配对重检。

HTTP 保留全局 300000 字节限额，仅 `workbook/preview`、`drafts/save`、`capabilities` 通过既有路由配置使用 2000000 字节，以容纳 1 MiB 文件的 Base64 和 JSON 外层。原文件限制仍为 1048576 字节，不把编码后长度当作原文件上限。实际 socket 回归分别验证 Content-Length 与分块传输、准确上限和超限拒绝；实际 Owner 回归用准确 1 MiB 的三表 XLSX 验证解析、能力查询、私有保存与恢复，不以无 Owner 或 app.inject 结果替代完整路径。

## 提交重试绑定当前草稿修订

浏览器的提交重试请求只属于一个准确的草稿 ID 和预期版本。成功恢复另一草稿、新版本或非 EDITING 状态时清除旧请求；发送前再次核对当前目标，不能只依靠某一导航入口清理。修改、新建或切换身份继续清除旧编辑请求，进入工作簿申请时也清除保存和提交请求。响应必须对应本次请求的草稿、版本和 requestId 才能用于页面跳转。

同一 EDITING 修订的网络失败重试保留原 requestId。已收到提交成功响应但后续重读失败时，也暂时保留原请求，避免恢复时以新 requestId 重复提交。读取失败不改变当前草稿或其重试请求；只有成功恢复才按返回状态协调缓存。服务端的幂等结果、私有草稿权限和独立审批规则不变。

专项浏览器回归在隔离 GitHub PostgreSQL 上运行真实构建产物，覆盖正常 A/B 连续提交、提交响应丢失、成功提交后重读失败，以及提交失败后切换草稿。测试核对实际 HTTP 请求、页面申请地址、两个草稿的提交结果及独立审批；故障只注入网络/请求边界，不替换 React hooks、生成客户端或领域 Owner。此专项不等于全页面人工验收或生产部署。

## 0073：主体与准确证照的来源授权隔离

ORG01 的 REVISE、VERIFY_REGISTRATION 只能以该 target 主体自身的 version 事实证明来源复用，不能借用其持有证照的来源。REVISE_LICENSE、REVOKE_LICENSE 则必须匹配草稿中 licenseTarget 的准确 id/version、非撤销断言及其真实所属主体，只有该准确版本输入的来源可建立免目录 WRITE 的维护例外。ADD_LICENSE 和 CREATE 不享有此例外，即使同一主体或其其他证照已有相同来源，也仍要求普通契约 WRITE。其他领域的对象授权及真实工作簿子输入 binding 追溯保持不变。

新的内部元数据投影明确记录 licenseTarget（不完整时为 null），解密时与已认证内容逐项比较。旧投影缺少该字段时，仅使用 V1 投影验证旧内容；不重写密文、摘要、版本或审批记录，也不在读取时补造 SQL 授权依据。旧证照编辑草稿可恢复，狭义维护者需编辑后显式保存为新修订，再使用准确证照来源提交；有普通契约 WRITE 的提交仍可按原授权完成。历史证照可继续作为底稿，但当历史来源不同于当前准确并发目标来源时，该来源切换需要普通契约 WRITE，而不是借用维护例外。

迁移 0073 仅前向替换授权函数，0071/0072 及其校验和不变。独立的 0072→0073 CI 先在旧函数下重现跨主体/证照来源借用，再在同库升级后验证相同草稿及 SQL 请求被拒绝，并核对全部既有表数据、迁移记录、函数所有者及 ACL 不变。回归同时核对合法修订、独立审批、Apply 和幂等，不能用总通过率代替授权反例。

## 异步工作簿上传只更新其拥有的字段

读取 File.arrayBuffer 期间仍允许修改接收治理范围。上传完成时，必须合并到 latestDraft 的最新状态，只替换 bytesBase64、失效 manifest 和预览，不回写开始读取时的 campus、metadata.campus、契约或保留期限。所有本组件编辑先同步更新 latestDraft，再通知父组件，避免同轮事件丢失。

每次新文件选择递增代次，较早读取晚完成时不得覆盖较新文件。更改契约同步使在途读取失效并移除旧文件，不依赖下一次 effect 才取消。身份切换、组件卸载及父组件的请求代次保护继续生效。浏览器专项延迟真实 File 的读取边界，核对双向院区切换、文件乱序完成及契约变更后的实际保存与服务端恢复；不模拟 React 状态或替换权限校验。
