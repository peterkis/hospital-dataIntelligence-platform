# 完整POC派生制品保留至证据基线整体处置

完整POC中已经成功提交的`managed_export_artifact`、清单、独立摘要以及与其关联的下载、交接、回执、对账和检查点证据，必须在隔离合成POC环境存续期间完整保留。管理界面、业务API、后台作业和日常运维不得对单个完成制品执行物理删除、自动过期、覆盖、重打包、原位脱敏或选择性清理；交付完成、对账通过或检查点推进都不产生删除资格。

后续来源发布、消费者交付配置、格式、模板、映射或用途发生变化时，只能通过新作业形成新派生制品。平台可以追加一条从旧制品指向后续制品的取代事实，用于说明同一消费者及用途当前应优先使用哪个制品，但不得借此修改旧制品的身份、精确字节、媒体类型、清单、摘要、证据或可追溯性，也不得把“已被取代”解释为失效、过期或删除。访问授权与制品存在性相互分离：权限撤销只阻断后续取得，重新获得授权后仍应解析到原`artifact_id`和相同字节。

失败尝试在进程内产生的临时字节从未取得制品身份，必须在尝试结束或进程恢复时丢弃；这属于失败执行清理，不是对完成派生制品的删除、过期或保留策略。失败作业、尝试序列和错误证据仍按既有只追加规则保留。

只有在完整POC不可覆盖证据包已经导出并完成清单、摘要、场景覆盖和关键制品字节复核后，才允许通过独立、受控且留痕的环境处置流程一次性销毁整个隔离合成POC环境及其中全部合成数据。该动作不是平台业务能力，不得通过管理界面或业务API发起，也不得选择性删除某个派生制品；环境处置前置条件、操作者和结果必须保存在被销毁环境之外。

本决策只冻结完整POC内的保留与删除语义，不把派生制品定义为永久保存，也不决定生产环境的法定保留期限、隐私删除、诉讼保全、归档分层、备份恢复、密码学销毁或存储容量。[ADR-0106](0106-set-managed-export-artifact-capacity-from-representative-measurement.md)独立确认容量先测后定及超限失败关闭方法，[ADR-0107](0107-use-two-stage-capacity-evidence-with-integrated-ratification.md)确认前置与集成后容量证据都必须进入不可覆盖证据链，[ADR-0108](0108-freeze-managed-export-capacity-workload-profile-matrix.md)冻结七类容量画像，[ADR-0109](0109-freeze-managed-export-capacity-field-distribution-rules.md)冻结逐字段分布和适用字段资格，[ADR-0110](0110-use-local-wsl2-anolis-8-9-for-capacity-simulation.md)冻结受限本机WSL2容量环境；重复次数、阈值、结果聚合和数值上限仍须后续确认。本规则不进入Phase 01，也不增加ABG-01至ABG-40、72个REST或20个界面场景；其应用行为作为G05、G07、G12和U18的必需参数化子用例，环境整体处置只作为完整POC验收后的受控收尾程序。
