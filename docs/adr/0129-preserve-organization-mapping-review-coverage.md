# 保留组织源映射提交身份与历史候选审阅覆盖

组织源映射输入首次暂存时的真实人员身份是提交人。该人的账号别名可以规划同一输入，但另一名拥有命名空间写权限的人员不能代替提交人冻结候选；最终审批人必须与原始提交人身份不同，独立资料核验不替代这项审批分离。

候选的冻结摘要和加密内容是不可变审批证据，不为适配新的读取契约而重算或覆盖。当前候选冻结全部原始输入行；旧格式候选未保存完整输入行时，只从已冻结的可执行命令恢复审阅行及物理行号，未保存的阻断原始行不能补造。`/review.entries` 表示可展示的输入行，`inputCoverage=COMPLETE` 表示完整冻结输入，`inputCoverage=LEGACY_EXECUTABLE_ROWS_ONLY` 表示仅可证明旧命令中的行；`commandFacts` 只表示可执行事实，`issues` 单独保留阻断信息。调用方必须同时展示覆盖状态和阻断信息，不能将空 `entries` 解释成没有输入或没有阻断行。

旧未批准或已批准未提交候选可以读取其保留的原冻结依据及覆盖限制，但不能跳过冻结摘要的失效检查继续审批或应用；需要从不可变暂存输入重新冻结并重新审阅。已提交候选保留原 outcome 恢复。0114 的 SQL 函数文本替换对已安装函数设有精确基线检查，以保留其身份和授权；后续函数调整应在新的前向迁移中优先使用显式 `CREATE OR REPLACE FUNCTION`，验证所有者和 ACL，不改写已应用的 0114 或账本。
