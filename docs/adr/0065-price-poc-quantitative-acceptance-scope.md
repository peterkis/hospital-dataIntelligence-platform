# 价表POC采用24个项目和不少于60个强制场景

价表POC使用24个合成收费项目稳定身份和至少36个项目版本，发布3个不可变完整价表快照并形成累计不少于72条价格条目；覆盖2个院区、门诊、住院、急诊、体检四类实际场景及通用通配模式，并至少包含6条院区差异价。五个合成外部代码命名空间合计至少建立40个代码身份、50个代码版本、36条语义映射和24条确定性操作绑定。邻接薄切至少包括2份政策来源资料及4条适用认定，8个医保目录项目、10条收费项目医保映射和4条待遇规则，6条收费资格规则，4项计价规则且每项至少4个测试向量，4个收费组套及至少16个组成项，8个医嘱目录项目、6个执行服务和12条医嘱收费映射规则，以及2个具有独立水位的仿真消费者。

验收执行不少于60个强制场景，其中至少12个导入及CRUD版本场景、12个时间院区及价格解析场景、10个外部命名空间及映射场景、10个计价规则组套及医嘱执行映射场景、8个权限审批紧急暂停及补偿发布场景、8个Outbox幂等缺口恢复回执及审计场景。REST API覆盖全部强制场景，管理界面至少覆盖16个代表性端到端场景。任一标记为强制的场景失败均不得用总体成功率抵消；真实系统联调和生产性能指标不属于该验收范围。

[ADR-0100](0100-stage-managed-export-after-phase-01-and-reserve-record-push.md)把`MANAGED_EXPORT_HANDOFF`纳入通过Phase 01架构门禁后的完整POC邻接薄切；[ADR-0101](0101-expand-managed-export-acceptance-baseline-to-72-rest-and-20-ui-scenarios.md)保留本决策的A01至F08共60个REST场景和U01至U16共16个界面场景，并新增G01至G12和U17至U20。因此完整POC的最终最低基线为72个REST场景和20个界面场景，既有60/16不得单独解释为受控导出或完整POC通过。
