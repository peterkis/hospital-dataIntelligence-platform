# 地点使用声明与可维护用途字典

用户批准 P3-07 由 location-master 唯一维护组织使用地点的声明及全院统一用途字典。关系固定组织类型、组织身份、院区、用途身份、地点身份及起点，地点改变使用原子 END+CREATE，不修改组织或人员归属。用途名称修订保留稳定身份和编码，含义改变另建条目。

相交期间内任一整地点声明独占即冲突，共享声明可并存。主要地点按组织类型、组织身份、院区和用途稳定身份约束。用途停用及上游失效只改变当前准入，不自动结束声明或释放占位，避免启用后责任和独占冲突。最新完整有限声明不回退旧开放声明，END 永久收缩并保留原 B/R 认知。

用途内容新建、修订及关系发布独立核验和审批。按用户明确决定，用途 ENABLE/DISABLE 是本字典限定的单人维护动作：当前人类维护授权、期待头、理由和实际 DB 时间，准确请求结果和审计同事务保存，无单独审批。此例外不适用于用途含义、未发布草稿、其他治理对象或关系发布。重新启用仅重核现有依赖，不重批原关系，也不消除历史停用期间。

用途内容也是保留原起点的完整声明。当前复核取 R 已批准的最高内容版本，不因较新有限内容已结束而回退旧开放内容；草稿仍不影响已批准内容。签审及启停事件采用身份内的追加序号，时间记录数据库实际操作时刻，不能以时间排序替代序号。原关系的准确用途版本与当前复核版本分别保留，改名可以改变当前依据，但不改变稳定编码、含义和主要地点约束。

所有写入口复用现有事务锁与 Catalog 结果机制，受限 SQL 独立守护最终授权、完整期间和冲突。代价是保守串行化和保留失效声明的显式收尾工作；不建设排程、子区域推断或通用字典平台。仅 TEST POLICY ONLY 合成 CORE，院方政策 NOT_ADOPTED、临床 NOT_READY、FULL 及阶段空间集成另行验收。

依赖边界读取必须在同一事务、同一R下先求请求B期间内实际贡献的Owner声明，再核验其来源权限。已安装0203之后的修复以0204替换Department公开边界函数，保留原函数身份和权限；旧迁移不回改。Department沿用既有属性版本实际期间遮蔽、有限后继结束后旧版本可重新贡献的规则，并保留生命周期和替换终止分段。这个读取规则不把地点使用或Nursing的永久遮蔽语义移植到Department，也不会免除实际贡献来源的当前权限。
