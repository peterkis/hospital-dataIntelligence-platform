# 组织工作簿作为一个原子应用单元

按用户批准的 P1-05 计划，ORG01、ORG02、ORG03 三个工作表与受控 typed 清单共同确定同一作业 revision。ORG01 文件 CORE 只承担任务锚点，各表仍使用自己的准确契约；文件 CORE 使用受约束的独立用途分类，保留既有通用和手工契约的身份与终态。

资料核验先绑定准确候选中的逻辑别名、证照和范围，再由独立审批批准整个依赖图。新主体和院区的配对由管理员限定到准确 job/revision；只有应用事务内由数据库实际生成身份后，才将预授权转换为精确对象权限。核验和审批可由同一人完成，但均不能由提交人的任何身份别名完成。

手工与导入共用事务绑定的领域写入入口；公共协调器持有唯一根事务。选择符号依赖和数据库签发身份，避免用试写回滚或预分配假 ID 模拟候选；因此候选不能逐行提交，最后一条领域写入或成功审计失败必须连同授权转换全部回滚。最多 100 条展开命令，不自动分包。

新作业不按文件内容去重为既有主体；原请求恢复读取原 outcome。输入或组合契约改变必须建立新 revision 并重新核验、预授权、审批。导入只维护资料与关系，不启用院区或授予实际运营窗口资格。
