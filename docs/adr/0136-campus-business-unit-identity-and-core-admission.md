# 院区业务单元身份、绑定与临床就绪分离

用户批准 P3-01 的业务单元由 care-organization 唯一维护。单元永久身份与
逻辑科室、院区和运营主体的期间绑定分别表达；同科室同院区可有多个单元。
跨院区显式重新绑定保留单元及科室 ID，在一个事务中结束旧绑定并建立目标，
不移动人员或物理地点。属性修订不覆盖已有绑定期间。

业务单元代码全院唯一且终身归属原单元，改码或关闭不释放。代价是不能用
院区内重复代码降低编码维护成本，但历史及跨院区身份解析保持明确。

独立 CORE 可在负责人为空时发布主数据，临床就绪仍未满足；非空未知人员
引用完整保留并阻断，不临时造人。正式职责关系属于 P5-02。筹建计划不是
运营批准，未来版本也必须有完整、独立批准的科室服务与运营许可覆盖。

收治限制通过准确规则版本及受保护材料的独立核验留证；无限制同样需要
明确确认。依据随单元版本冻结，本票不执行患者规则或授予临床能力。

绑定准入在同一 R 下通过上游公共 port 验证完整期间。永久关闭为非扩张
路径，不重复已失效上游的扩张准入，但保留当前授权、期待版本及独立审批。
已有结果先恢复准确原接受事实再检查当前权限，旧历史不被当前复核改写。
本 ADR 仅为 TEST POLICY ONLY 合成开发，不代表院方政策或正式医院验收。
