# 长期保留生产消费架构并在POC使用同契约仿真

长期价表架构保留中央编制、审批发布、事务Outbox、变更通知、不可变发布快照、增量游标、消费水位、回执、版本缺口检测和重放能力。发布事件只通知对象、版本、摘要和稳定快照获取引用，权威内容仍来自平台API或不可变发布快照，不能把事件载荷建设为第二份主数据。消费者以事件ID幂等，按治理对象或聚合版本顺序应用，发现缺口时暂停该对象的后续应用并请求快照或缺失版本；消费者失败不回滚已经完成的平台发布，也不采用跨平台与消费系统的分布式两阶段提交。现阶段只使用隔离仿真消费者验证相同API、事件包络、幂等、顺序、缺口、重试、补偿、回执、审计和回退契约，不连接真实HIS、LIS、PACS、医保或财务系统，也不把生产消息集群、CDC、缓存、SLA、灾备和影子计费列为POC依赖或验收承诺。未来真实接入只替换传输适配器和消费者实现，不改变价表发布语义。Phase 01快照的具体存储与下载边界见[ADR-0093](0093-store-canonical-snapshot-bytes-in-postgresql-transactionally.md)。
