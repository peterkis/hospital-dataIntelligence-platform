# 采用前置可行性实验与集成后真实链路核验的两阶段容量证据

完整POC的派生交付制品容量采用两阶段证据模型。第一阶段在Phase 01全部架构门禁通过后、`MANAGED_EXPORT_HANDOFF`业务薄切实施前执行前置可行性实验；第二阶段在该薄切完成集成后，通过实际`release-distribution`和冻结公共下载API执行真实链路核验。两个阶段必须引用同一组已冻结的负载画像、运行环境、测量方法和判定阈值，并对结果差异进行可追溯比较。

前置可行性实验由现有TypeScript验证工具链承载，使用一次性、隔离且不进入业务运行的容量试验装置，覆盖候选确定性ZIP生成、与ADR-0104相同物理形态的PostgreSQL写入/读取以及受控下载与摘要核验。试验装置不得成为业务API、正式物理DDL权威、运行时制品、第二套实现、独立服务、模块、workspace或生产基线；其结果可以支撑后续ADR冻结业务薄切的实施上限，但单独不能形成完整POC最终验收资格。

业务薄切集成完成后，必须使用同一冻结画像、环境、测量方法和阈值，通过实际`release-distribution`生成、原子持久化并由正式平台下载API取得制品，重新采集ADR-0106规定的全部容量指标。只有这次集成后核验通过，容量基线才取得完整POC最终验收资格；不得用前置试验结果、内部函数基准、数据库直读或非公开测试路径替代。

如果集成后结果未达到冻结阈值或不能支撑已经冻结的实施上限，完整POC必须失败关闭。平台不得静默放宽、改用另一画像、选择较优轮次或把前置结果覆盖为通过；后续只能以新证据和新ADR调整容量上限，或重新确认流式生成、数据库读取及替代存储架构。任何提高容量上限的决定都必须重新完成受影响的两阶段证据；降低上限也必须显式修订ADR并重跑边界用例。

两阶段的输入身份、生成器与代码版本、环境摘要、原始测量、汇总、差异解释、判定结果和ADR引用必须进入同一不可覆盖证据链。[ADR-0108](0108-freeze-managed-export-capacity-workload-profile-matrix.md)进一步冻结负载规模与压力画像矩阵；[ADR-0109](0109-freeze-managed-export-capacity-field-distribution-rules.md)冻结短中长分布、目标长度、宽度、CSV字符/转义类别、适用字段身份和失败关闭语义，并要求两阶段使用同一字段分布版本；[ADR-0110](0110-use-local-wsl2-anolis-8-9-for-capacity-simulation.md)冻结本机WSL2 Anolis OS 8.9、8 vCPU、4 GiB、无swap、10 GiB根磁盘和独占运行证据，并要求两阶段使用同一环境版本。重复次数、峰值RSS/磁盘余量/时间阈值、结果聚合及最终MiB数值仍须后续确认。本决策不增加Phase 01 ABG、完整POC REST或界面场景编号，也不授权Phase 01预建受控导出或字段分布资产。
