# 瞬时技术故障在同一冻结导出作业内有限重试

`MANAGED_EXPORT_HANDOFF`必须区分确定性数据转换错误与技术故障。值、类型、必需映射或声明约束错误继续按[ADR-0099](0099-fail-the-entire-managed-export-job-on-any-record-conversion-error.md)使作业终态转换失败，只能在修正相应发布或版本后新建作业；只有被作业所冻结重试策略明确列为可重试的进程崩溃、临时存储、数据库、I/O或同类瞬时技术故障，才可在同一冻结作业内自动重试。未知或未分类技术错误不得自动重试。

初始化导出作业冻结不可变重试策略版本；该版本明确可自动重试的稳定错误分类、有限自动尝试额度和退避规则，具体次数与时长属于版本化配置而不是硬编码领域常量。每次执行都以正数且不复用的`attempt_no`追加一条`consumer_initialization_attempt`证据，并从固定规范快照、冻结消费者交付配置、契约、模板、映射、格式和算法完整重建；不得从上次处理成员或部分字节续跑，失败尝试的临时字节不取得制品身份、不能下载或交接，日期时间也不承担尝试排序权威。

自动尝试额度耗尽或遇到未知技术错误时，作业进入`TECHNICAL_ATTENTION_REQUIRED`并生成影响事项，保持零个完成制品。具备该作业对象级权限的人员可以在确认技术条件恢复后对同一冻结作业发起一次受控重试，追加一个新尝试但不重置已耗尽的自动额度，也不得改换来源发布、规范快照、消费者、订阅、交付配置、重试策略、格式或算法；再次失败则重新进入待处置。任何冻结输入需要变化时必须新建作业。

任一后续尝试成功时，作业仍只能形成一个完整、不可变、非权威派生交付制品，全部失败及成功尝试、错误分类、授权动作和影响事项继续只追加保留。[ADR-0103](0103-use-deterministic-uncompressed-zip-for-managed-export-artifacts.md)进一步冻结该完整重建所使用的派生交付格式版本，并要求相同冻结输入生成逐字节相同的ZIP。该规则在G05和U19中增加必需参数化子用例，不增加或减少[ADR-0101](0101-expand-managed-export-acceptance-baseline-to-72-rest-and-20-ui-scenarios.md)冻结的72个REST与20个界面场景，也不进入Phase 01的ABG-01至ABG-40。
