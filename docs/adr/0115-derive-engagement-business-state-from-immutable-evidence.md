# 任用业务状态由不可变关系期间和只追加生命周期证据推导

任用的 `PLANNED`、`ACTIVE`、`SUSPENDED`、`ENDED` 业务状态不保存为 Person、
稳定任用关系或治理对象上的可变当前列，而由指定 `recordAsOf` 可见的最新任用期间
版本、只追加 `SUSPENDED`/`RESUMED` 证据及 `businessAt` 共同推导。结束通过追加新的
任用期间版本冻结 `businessValidTo`；普通命令不得重新打开已结束关系，真正再次任用
必须创建新的 Engagement ID，只有保留旧知识历史的显式有效期纠错可以修正错误结束
日期。该选择牺牲了单行当前状态更新的便利，以保留双时态重现、并发保护和业务状态
与治理工作流状态的独立主权。

POC V1 中暂停不释放任用期间对重叠规则的占用；结束缩短期间后，超出新结束边界的
未来区间才不再参与重叠。若未来需要计划性暂停、暂停释放占用或通用事件纠错框架，
必须另行确认政策与时态语义，不能通过新增同义状态或更新历史事件实现。
