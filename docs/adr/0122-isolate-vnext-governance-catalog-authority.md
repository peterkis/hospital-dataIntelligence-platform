# 以独立原生 SQL lineage 管理 vNext 治理目录

根据 P0-01 的显式授权，目录专用控制平面在 receipt 绑定的新库中建立；旧业务 schema、生成类型和证据库不迁入。governance-catalog 是唯一元数据写 Owner，受限 SECURITY DEFINER 命令校验当前主体、scope、exact head 与复核摘要，将版本、事件、outcome 和最小审计同事务保存。应用角色仅执行有限函数；只读表权限供元数据类型发现，RLS 默认拒绝行读取。DB schema owner 为本地迁移管理员，不能宣称管理员无法绕过治理机制。

目录对象与源字段声明分开保存；来源主目录保持 DRAFT/待院方确认，合成治理使用独立 SYNTHETIC scope。责任范围只接受 ALL/NORTH/SOUTH 与 ALL/IDENTITY/CONTACT 的有限集合，按覆盖关系和半开期间冲突检查；所有目录命令在同根事务串行化，不提供自由范围表达式。修订为新完整版本，旧发布与旧 R 保留；未发布修订不会移除既有已发布 Owner 的冲突防护。


PR #2 的 0007 将 ADR 0009 应用于目录：范围许可后再检查精确对象 UUID、类型、院区、用途、字段组和操作。合成创建策略在创建事务内为新对象配置明确授权；既有对象不继承策略。发布审查原/拟发布有效时间线的全部权限维度，废止审查全部有效定义。目录的不同 B 起点是定时定义，同起点后发版本修正该起点断言；按发布顺序覆盖局部区间，并检查整个拟发布责任时间线。该算法不替代业务 E/A 的完整区间规则。审计流读取也须专门授权。


0009 对来源定义统一采用 B/R 有效区间：单一固定父版本的递归有效片段须覆盖完整子期间，发布重新验证，不自动替换固定引用。资格按同一 R 下的指定 B 选择并授权每层实际版本。影响义务覆盖全部仍有效的版本片段，部分恢复不能关闭剩余片段；历史判断不可覆盖，当前新发现用独立 case_id 的升级观察补充。这些规则仅用于 SOURCE 元数据资格，不构成真实 apply 授权，也不替代 E/A 区间算法。

0010 的来源 PUBLISH/RETIRE 审批冻结拟变更后的完整影响清单，而非仅审批变更前引用快照。稳定知识水位取现有目录/影响事件的最大记录时间，另绑定目录 head；无事实变化时重复读取不会因墙钟推进改变摘要。命令串行锁内重算、检查当前权限并校验摘要，将审批人身份、请求、原因、内容和摘要与治理事件同事务绑定。影响触发器只消费该记录的 opening/closing，不在批准后重新决定影响。旧记录的 NULL assessment_head 和当前升级观察明确不代表历史操作已取得此审批。

0011 将每个来源影响 case 约束在该事件新增的失效区间，关闭只要求该 case 的义务区间已无失效交集。义务与推导依据随 closing 一并冻结；旧审批按其原知识时点派生事件区间并显式标记，不修改原审批摘要、影响事件、历史决定或审计。未批准旧 case 仅是原记录时点的失效观察，不据此追认审批。详见目录导入与影响文档的事件区间义务。
