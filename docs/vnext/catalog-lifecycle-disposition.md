# 目录与来源生命周期处置

PR #2 的审查补充。本文件明确当前能力及尚未实施的承接要求，不把后续票标为通过，也不授权执行 P0-02/P8。

| 生命周期 | P0-01 当前行为 | 未覆盖部分的承接 |
|---|---|---|
| 候选、核验、启用 | CREATE/REVISE → SUBMIT → 不同身份 PUBLISH | 元数据发布，不等于真实系统上线或正式来源批准 |
| 未退役内容纠正 | REVISE 追加新完整版本；重新复核/发布；旧版本和旧 R 保留 | 当前已实现 |
| 新候选待审/被退回 | 候选 head 与已发布权威分别读取；旧已发布来源继续有效 | 当前已实现；新版本发布或明确 RETIRE 才改变权威 |
| 永久结束 | RETIRE 要求当前 REVIEW 权限、与被废止版本编制者不同的身份、该已发布版本内容/期间摘要及当前 candidate head；保留历史并拒绝新的受信采用 | 当前已实现；有未批准候选时仍可独立复核并结束既有权威，不把永久退役伪装为暂时暂停 |
| 临时暂停 / 恢复 | 当前没有 SUSPEND/RESUME 命令；不得用 RETIRE 后“自动恢复”模拟 | P0-02 承接来源引用资格契约与状态定义；P8-07 承接治理目录维护命令/页面的实现与全生命周期验收。在相应交付前为 NOT_READY |
| 已退役目录/来源的纠正 | 不修改已退役版本，也不复活同一对象；当前 API 明确拒绝 | P0-02 承接新候选及显式 supersedes/corrects 引用契约；P8-07 承接退役后纠正命令、历史展示和验收；当前 NOT_READY |
| 已退役对象的替代 | 当前可登记另一个技术码的新身份，但尚不能声明其为旧对象的受控替代关系 | 显式替代关联、依赖影响和维护验收同样由 P0-02/P8-07 承接；未建立该关系前，不宣称“替代完成” |

这里的承接是本次审查明确的待交付要求。后续执行仍须读取相应票并由用户选择；如其具体任务边界不容纳新增治理工作，应先拆出受控补充票，不能静默跳过或借此自动扩大本轮实现。

临床/人事/机构等业务对象的暂停、恢复、结束、更替继续由各自 P1–P7 Owner 票承担，不能套用此目录状态机替代业务事实。

维护 `GET /api/vnext/catalog` 和详情/history 返回 head/历史认知，包含未批准候选，不是有效权威读取。`GET /api/vnext/catalog/effective?scope=SYNTHETIC&businessAt=<本地B>&asOf=<可选R>` 单独读取有效元数据：先选 R 截止前按 head 排序的最新 PUBLISHED/RETIRED 事件，再验证其版本覆盖半开 B。DRAFT/REVIEW 不替换已接受版本；RETIRED、未来或已过期的最新接受版本被排除，不回退捞取旧版本。DATASET、RESPONSIBILITY 和 SOURCE 使用相同规则；SOURCE 的受信引用仍须额外通过递归来源资格 port，元数据有效不代表真实接入已批准。R 只筛选知识范围，授权始终用当前身份。

废止页面先载入并展示被结束的已发布版本完整内容、期间和摘要，再允许独立复核者提交。存在候选时，废止摘要绑定已发布版本，expectedHead 仍绑定当前候选 head。新命令按动作封闭字段：CREATE/REVISE 携带版本内容/B，SUBMIT/REJECT 仅目标/head，PUBLISH/RETIRE 另带复核摘要；不适用字段不能被静默忽略。
