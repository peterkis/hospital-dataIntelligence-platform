# 目录与来源生命周期处置

PR #2 的审查补充。本文件明确当前能力及尚未实施的承接要求，不把后续票标为通过，也不授权执行 P0-02/P8。

| 生命周期 | P0-01 当前行为 | 未覆盖部分的承接 |
|---|---|---|
| 候选、核验、启用 | CREATE/REVISE → SUBMIT → 不同身份 PUBLISH | 元数据发布，不等于真实系统上线或正式来源批准 |
| 未退役内容纠正 | REVISE 追加新完整版本；重新复核/发布；旧版本和旧 R 保留 | 当前已实现 |
| 新候选待审/被退回 | 候选 head 与已发布权威分别读取；旧已发布来源继续有效 | 当前已实现；新版本发布或明确 RETIRE 才改变权威 |
| 永久结束 | RETIRE 要求当前 REVIEW 权限、与被废止版本编制者不同的身份、该已发布版本内容/期间摘要及当前 candidate head；保留历史并拒绝新的受信采用 | 当前已实现；有未批准候选时仍可独立复核并结束既有权威，不把永久退役伪装为暂时暂停 |
| 临时暂停 / 恢复 | 当前没有 SUSPEND/RESUME 命令；不得用 RETIRE 后“自动恢复”模拟 | P0-02 承接来源引用资格契约与状态定义；P8-07 承接治理目录维护命令/页面的实现与全生命周期验收。在相应交付前为 NOT_READY |
| 已退役目录/来源的纠正 | 不修改已退役版本，也不复活同一对象；当前 API 明确拒绝 | P0-02 承接新候选及显式 supersedes/corrects 引用契约；P8-07 承接退役后纠正命令、历史展示和验收；当前 NOT_READY |
| 已退役对象的替代 | 当前可登记另一个技术码的新身份，但尚不能声明其为旧对象的受控替代关系 | 显式替代关联、依赖影响和维护验收同样由 P0-02/P8-07 承接；未建立该关系前，不宣称“替代完成” |

这里的承接是本次审查明确的待交付要求。后续执行仍须读取相应票并由用户选择；如其具体任务边界不容纳新增治理工作，应先拆出受控补充票，不能静默跳过或借此自动扩大本轮实现。

临床/人事/机构等业务对象的暂停、恢复、结束、更替继续由各自 P1–P7 Owner 票承担，不能套用此目录状态机替代业务事实。

维护 `GET /api/vnext/catalog` 和详情/history 返回 head/历史认知，包含未批准候选，不是有效权威读取。`GET /api/vnext/catalog/effective?scope=SYNTHETIC&businessAt=<本地B>&asOf=<可选R>` 单独读取有效元数据。0007 修正原 0005 的单一最新版本算法：先取 R 内已发布定义，同一 B 起点仅保留最后一次修正；不同起点的定义按发布顺序覆盖其半开区间。根据所得有效区间匹配 B，再选择结果。因此未来定义尚未生效时原定义仍可用；同起点缩短期限不复活被替代的同起点旧版本。不同起点的局部覆盖结束后可能重新显露早期定义，所以责任发布必须检查整个拟发布时间线的 Owner 冲突。DRAFT/REVIEW 不参与有效区间；当前 R 已知的 RETIRED 永久结束整个对象。旧 R 仍能读取当时定义，但始终检查当前对象权限。

上述规则适用于目录定义，不能作为 E/A 业务实体的区间算法。SOURCE 的受信引用仍必须额外通过递归资格 port；0009 要求同一 R 下各层固定父版本与 B 有效定义一致。目录有效展示本身不授予真实 apply 权限。

废止页面先载入并展示被结束的已发布版本完整内容、期间和摘要，再允许独立复核者提交。存在候选时，废止摘要绑定已发布版本，expectedHead 仍绑定当前候选 head。新命令按动作封闭字段：CREATE/REVISE 携带版本内容/B，SUBMIT/REJECT 仅目标/head，PUBLISH/RETIRE 另带复核摘要；不适用字段不能被静默忽略。

0006 要求 SOURCE RETIRE 另带当前引用影响摘要，SOURCE 重发且存在当前引用时也必须核对影响；其他目录类型不接受该字段。来源变化引起的问题通过独立复核的下游合格重发或废止关闭，保留原引用、问题事件和精确 resolution_event。见 [导入审计与来源影响问题](catalog-import-and-impact.md)。


0008 的读取边界：effective 与来源 qualification 只读取已接受定义，当前精确授权应匹配该定义，而不额外匹配无关候选 head。因此仅创建或提交候选不能使原权威失去读取资格。主体禁用、范围撤权、对象维度撤权和来源引用用途撤权仍立即拒绝，即使请求旧 R。写命令继续核验候选及其会影响的已发布/拟发布时间线权限。


0009 将 SOURCE 的资格、固定引用准入和影响判断统一到已发布定义的有效区间。资格请求在一次 R 下按 B 选择版本，再核验每层固定父版本和当前用途授权；未来版本不使较早 B 的原定义提前失效。CREATE/REVISE 必须由单一父版本的递归有效区间覆盖完整子期间，PUBLISH 再次核验完整覆盖与无循环，跨父版本的子期间必须拆成明确版本，本票不引入自动分段引用。资格页面可选择业务时间，并显示实际采用版本；时间改变使在途旧资格响应失效。

影响枚举覆盖所有仍有有效片段的已发布下游版本，展示 effectiveSpans 与 affectedSpans。来源变动后只对无法由固定链路支持的片段登记 OPEN；独立复核的下游发布/废止只有消除该受影响版本全部不支持片段才关闭，保留精确 resolution_event。历史提前 CLOSED 不被改写；升级在仍有不支持片段且无 OPEN 义务时追加独立的 UPGRADE_TEMPORAL_IMPACT_OBSERVATION 和审计，以当前观察补充历史。case_id/event_sequence 主键与追加保护不变，原按来源事件/版本/序号的冗余唯一约束不再阻止不同 case_id 的真实再观察。
