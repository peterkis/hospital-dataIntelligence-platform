# 组织空间工作台操作

入口：`/admin/vnext/care-space`。本页仅用于合成 CORE；依据批准、工程验证与临床或生产验收分别记录。

先独立批准基础对象，再选择准确对象引用建立关系。事实与历史区按原 Owner 分页、读取 B/R、准确版本和差异。维护按钮读取原受保护来源行，绑定当前准确头；编辑人仍需核对新的期间、契约和材料。

编辑可以不完整。保存私有草稿后，刷新根据服务器修订恢复；过期保存不会覆盖服务器。草稿只属于原底层身份，同人别名仍为同一个编辑人。完成编辑后暂存原申请，依次预检、独立核验、冻结、审阅批准、apply、回读及 reconcile。只有 `COMMITTED` 与 `MATCHED` 同时确认才显示完成。

文件导入先下载准确契约模板，选择 CSV/JSON/XLSX，并填写原 Owner 的操作清单。文件内容及原请求先保存到服务器。问题附工作表、原始行与字段，可以下载问题清单。纠错使用“以新修订纠正原文件”，再次上传并接收；原文件、原回执和原问题保留。URL 中的 `draft/fileRequest/fileVersion` 只定位准确服务器记录。

保存、暂存或 apply 的响应不确定时保留原 requestId。刷新或使用恢复操作读取同一请求，不能改号重试。冻结、批准与 apply 会重新检查当前权限、期待头及准确依赖，旧预检不会永久授权。核验、审批与护理确认必须满足原独立身份要求；地点用途字典保留原已批准的单人维护例外。

一致性区填写完整半开窗口及准确对象或已暂存成员。结果区分 `SATISFIED/NOT_SATISFIED/UNKNOWN`，成员结束、关闭或暂停后的无效期间不会计作覆盖。影响读取只识别已经接入的依赖；未接入的人员、床位、患者及外部能力继续列为 `NOT_EVALUABLE`。暂停不会自动释放责任或独占关系，独立 END 不等于交接完成。

暂存输入的时间问题使用原 Owner 的失败检查和贡献边界定位。`INTERVAL` 表示准确反例；`ROW/BUNDLE` 表示整行或整包问题，此时窗口只是评价上下文。分段通过不会取消原完整窗口要求，也不会改变原输入、核验、冻结或审批。历史知识按共同 R 解释，读取材料及每项依赖仍需当前权限。

历史对象问题按原 Owner 在共同 R 中实际贡献的版本定位输入和原始行；跨版本窗口逐段展示来源，普通缺口不读取其他版本的私有申请。科目边界及释放时权限复核保留原采纳锚点和实际窗口贡献版本，过期或完全遮蔽的无关版本不扩大读取范围。已选中的过期版本仍产生缺口，不能回退到旧版本补足。

参数值、科目采纳和护理分区位于依据维护区。参数值与科目采纳在原 Owner 执行前，将完整命令和原业务请求 ID 加密保存到私有草稿存储；URL 的 basisRequest 只定位服务器记录。响应不确定时编辑及切换锁定，刷新恢复准确正文，再以原 ID 查询或重放原 Owner outcome。保存请求与业务请求使用不同 ID，保存依据命令不会写入领域事实。引用选择带入准确版本及必要摘要；科目代码和分区选项绑定所选准确版本。新增依据后使用“重新读取当前引用”，既有编辑不会被自动换成新版本。

本地开发数据库只使用 `npm.cmd run prototype:db:with -- <npm-script>`。原始0001–0252迁移和历史失败证据必须保留。完整工程验收以 `.runtime/vnext/p3-10/` 最终交接列出的固定候选、原始日志及实际浏览器证据为准；本说明和构建成功本身不表示验收通过。

本票完整入口为 `vnext:p3-10:validate`（fresh）、`vnext:p3-10:validate --upgrade`（准确原0252前驱）及 `vnext:p3-10:regression`（全部受影响检查）。浏览器使用 `vnext:p3-10:browser` 的 owned 临时库；保留研发库使用 `vnext:p3-10:deploy`，核验准确 receipt 后追加0253及之后的迁移，保全旧行多重集、重复数量、列、ledger、ACL和密钥。浏览器运行结束只写该运行报告给出的准确 stopFile；保留库始终保留。

保留库部署入口绑定本票已保存的原 checkpoint 或 receipt 相符的恢复 seed。缺少两者时拒绝，不能另建科室、草稿或执行请求替代原流程。已有 candidate 先查询原 outcome；仅原请求尚无 outcome 时进入独立审批及应用，已提交结果按原 ID 恢复并核对 reconcile。
