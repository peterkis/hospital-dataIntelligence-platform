# P2-05 科室演变设计与验证索引

本票实现合成 CORE 的科室 RENAME、SPLIT、MERGE。Department Owner 持有写权；一次输入修订对应一个完整事件，经独立材料核验、冻结、独立审批后原子应用。JSON 和固定三表 XLSX 使用同一模型和同一应用端口。

批准的范围来自 2026-10-01 用户确认的 P2-05 计划，以及 ADR-0025、0026、0028、0029、0030、0130、0131。P2-06 保留依赖处置与回执，P2-07 保留维护 UI，P2-08 保留通用暂停、恢复、院区关系和补偿。下游人员、患者、账号、库存、财务、消费者数据均不自动迁移。

## 事件与时间

| 事件 | 身份与关系 | 正式写入 |
| --- | --- | --- |
| RENAME | 一个既有科室；ORG27 同 ID 明细为版本证据，不进入身份承继图 | 同 ID 的新名称版本、事件、同 ID 前后版本明细 |
| SPLIT | 一个前身、至少两个新后继、每个后继一条承继说明 | 新身份与初始版本、事件、全部明细、前身被替代事实 |
| MERGE | 至少两个不同前身、一个新后继、每个前身一条承继说明 | 新身份与初始版本、事件、全部明细、全部前身被替代事实 |

T 为 Asia/Shanghai 本地业务时间，支持微秒和历史补录。共同 R 由数据库实际写入时间产生，事件、科室版本、明细和退出事实使用同一个 R。来源 `recorded_at` 单独保留，不能设置平台 R。

属性版本保留局部覆盖语义。`expectedVersion` 锁定最新乐观版本；事件的前身引用锁定实际包含 T 的版本，二者可能不同（例如最新版本只修订了过去一个有限区间）。接受的未来属性版本阻断演变。拆并追加独立 `replacement`，防止旧开放属性版本在 T 后恢复前身准入：新 R 且 B<T 仍有效，B≥T 返回 SUPERSEDED；旧 R 继续复现原认知。准确历史版本和冻结层级快照不改写。

后继 ID 由数据库生成。ORG04、ORG26、ORG27 的来源 ID 均为别名，结果 `aliasMap` 提供正式 ID/版本和原始行对照。后继正式代码独立创建；ORG23 永久代码归属仍适用。新后继不自动获得前身的院区关系、层级位置或权限。

## 17 个字段的落位

| 数据集/字段 | 保存与校验 |
| --- | --- |
| ORG26.org_event_id | 事件来源别名；结果映射到新事件 ID |
| ORG26.change_type | 当前契约、代码集和精确来源版本采纳；CORE 仅三类 |
| ORG26.effective_at | 本地微秒 T，关联前身、代码、契约和来源有效期 |
| ORG26.decision_ref | 冻结批准文号和受保护 `decisionEvidenceId` |
| ORG26.reason | 不可变事件事实 |
| ORG26.historical_reporting_rule | 冻结声明；不执行报表重算 |
| ORG26.migration_plan_ref | 与 `migrationEvidenceId` 成对；适用时必须提供并核验 |
| ORG26.recorded_at | 来源记录时间；独立于平台 R |
| ORG27.succession_id | 明细来源别名；事件内唯一，结果返回正式明细 ID |
| ORG27.org_event_id | 必须等于本事件来源别名 |
| ORG27.from_target_type | CORE 必须 ORG，并有当前代码集采纳 |
| ORG27.from_target_id | 精确解析既有 typed Department 引用与有效前身版本 |
| ORG27.to_target_type | CORE 必须 ORG，并有当前代码集采纳 |
| ORG27.to_target_id | 更名为同 ID；拆并为本批 ORG04 新目标别名 |
| ORG27.transfer_scope | 逐边保留范围；非空；不解释为自动迁移命令 |
| ORG27.context_rule | 拆分逐边必填并绑定 `contextEvidenceId`；实际去向由独立材料核验 |
| ORG27.recorded_at | 来源记录时间，与平台 R 分开 |

ORG04 新后继复用当前 18 字段、CREATE/NEW、材料、时间、代码集及来源准入。有效起点必须精确等于 T。既有正式对象不能作为新后继。FULL、其他事件和其他 target 保留完整输入并阻断，不能筛掉坏行后继续。

人员、患者、账号、库存、财务、来源映射、层级、消费者八个域均提供 AFFECTED/UNAFFECTED/UNKNOWN、责任角色、签审人、决策引用、依据、材料 ID。AFFECTED 还必须有处置要求。UNKNOWN 或缺少任一域阻断。核验记录逐域确认外部 Owner 签审与处置材料，绑定完整输入 digest 和 T。Department 核验人验证材料是否齐备，不代替外部 Owner 的专业结论；未实现系统不宣称已自动扫描。

合成契约采用有限 MACHINE 处理器检查“独立材料门禁完整”，其六个源条件的文本/版本仍来自冻结来源。这不是自动证明材料真实性，也不是医院政策采纳。合成政策状态为 PENDING。核验人与提交人按底层自然人身份分离；审批人与提交人分离；核验人与审批人可相同。服务账号不充当人工身份。

## 权限、冻结与事务

输入和核验使用加密不可变封装。冻结摘要包含完整输入、所有原始字段、核验 digest、契约精确版本、前身最新及 T 时版本、来源版本、材料 digest、影响声明、新目标事实和展开预算。冻结读取和恢复仍检查当前权限。新应用重验材料有效期和内容；已提交 outcome 在原材料 TTL 到期后可恢复，但当前材料 READ/来源权限撤销仍阻断。

ApplyCoordinator 仅调用一次演变事务端口，不循环调用根应用。串行锁、事务 ID 和 HMAC 写票限定数据库写权，受控 SQL 再检查候选、审批、身份、引用和关键不变量。事件、后继、版本、代码归属、边、退出、审计和根 outcome 同事务提交。最终延迟约束校验基数、复合版本身份、共同 R、退出边界和跨已接受历史图的无环性。任何阶段失败全部正式事实回滚，输入和失败诊断保留。

公共预算保持 100 条展开写入和 512 KiB 冻结计划。拆并计数为 `1 + 4×新后继数 + 明细数 + 前身数`（身份、版本、永久代码对象、初始代码断言）；更名为三条。20 后继拆分为 102，整事件拒绝；不拆包。P2-01 的行独立策略保持原义。

Department 当前读取、期间覆盖、事务引用、普通 REVISE、层级最终发布的节点和负责人科室、ORG22/ORG23 新建与扩张均接入退出边界。已接受映射、标识、层级保持原事实；明确 END/RETRACT，以及目标/语义不变的 ORG22 区间缩短等安全收缩可继续。事件结果交接状态为 NOT_EXECUTED。原始候选返回前也检查所有引用来源的当前 READ，失效或未解析材料引用不影响原始坏行纠错。

## API 和 XLSX

`/api/vnext/organization-evolutions/` 下的 template、files、inputs、inputs/read、preview、validate、verify、plan、review、approve、apply、resume、list、query、history、graph 均有封闭 TypeBox DTO、OpenAPI 和生成客户端。HTTP 预校验拒绝未知字段及隐式类型转换；编译样例覆盖错误 Owner、私造来源字段、缺域核验和数字时间的拒绝。

Department 原有版本比较接口同步支持有限的结构化 `sourcePin`。比较按规范化内容判断相等，复制同一来源钉选不会产生伪差异；从演变版本转为普通修订时，来源信息的差异仍能通过封闭 HTTP 契约回读。

原始来源授权在日期规范化之前执行，覆盖 stage、inspect/preview 和 verify；缺失前身在 SAVEPOINT 内判定，保留坏输入而不污染事务。readInput 保留纠错读取，preview/validate/plan 返回 BLOCKED_DEPENDENCY，冻结计划没有可执行命令；任何可解析来源的 ACCESS_DENIED 仍向上抛出。核验在写入接受记录之前读取并认证事件、逐域和 ORG04 后继的准确材料、契约及时间绑定。重复 plan 命中既有冻结结果时，仍通过完整 candidate/authorizeFrozen 授权，保持原 digest；过期材料不强制重规划，但新的 apply 会被拒绝。事件 list 复用完整 snapshot 授权，仅过滤 ACCESS_DENIED。

通用敏感读取在释放原件或派生 RAW_CELL/ERROR_REPORT 字节之前，认证该 FILE 修订绑定的完整 `EVOLUTION_INPUT_V1` 封装、HMAC digest 和原件/job/revision/campus 对应关系，再由 Department 的有限端口检查所有原始来源。客户端不能提交、删减或替换来源清单。业务坏行仍可在来源权限充分时读取原件；无法完整解析而未建立可信输入的原件继续隔离，原件和诊断不删除。测试管理员独立认证加密原件并比较全部字节，不能以管理员读取替代公共权限断言。缺少新读取协议的旧前缀对演进原件拒绝释放字节。

XLSX 固定 ORG26/ORG27/ORG04，事件恰好一行，更名 ORG04 仅表头。受控清单独立提供前身引用、期待版本、名称、材料与影响声明。原件通过 P0 隔离、魔数和活动内容防护；有界解析保持 1 MiB 文件、两个工作线程、64 MiB 堆和 2 秒任务限制。隐藏工作表/行列、公式、未知列、数字 ID 不放宽。源行包含表头偏移；坏行保留原件和诊断，整事件不能应用。
