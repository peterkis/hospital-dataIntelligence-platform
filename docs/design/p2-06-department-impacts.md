## Record and API decisions

Catalog owns immutable assessment/case identities and append-only case events. Department signs a transaction-bound ticket and supplies semantic observations; Catalog never reads the Department key. Finite SQL readers only query Department-owned hierarchy, mapping and identifier facts. Admission checks both 2,000 references and 524,288 UTF-8 bytes of the complete assessment serialized as PostgreSQL `jsonb::text`. Both limits return `PLAN_INPUT_LIMIT` with `{kind, observed, limit}` through HTTP; presentation pagination never cuts the approval basis.

`/api/vnext/department-impacts/` provides assess, assessment read/list, case read/list, assign, disposition, independent approval, recheck, receipt and assigned-service handoff read. Closed TypeBox schemas, generated OpenAPI/client and negative compile examples define the input boundary. Actor identity comes from the development server identity adapter.

P2-05 verification either selects an exact existing assessment or records one before verification. New inputs and independent reviews enumerate nine unique domains, including IDENTIFIER. Frozen approval binds the digest, rules, material and complete references. Apply repeats the observation under the shared advisory lock; SQL repeats the reverse dependency comparison and complete-domain guard. Automatic unsatisfied mapping/identifier/hierarchy references require AFFECTED declarations. Historical eight-domain records have a separate read-compatible shape and cannot authorize a new application. Manual review never changes NOT_EVALUABLE machine coverage.

A complete negative review remains recordable and invalidates an earlier positive approval. It cannot authorize a new plan or apply. This preserves the ability to withdraw an Owner attestation while rejecting an incomplete domain list or a conflicting UNAFFECTED declaration.

Closure proofs bind the exact Owner object/version/candidate/request. A closed hierarchy requires its closure candidate. Safe shrink compares directly against the case's original reference, including precise mapping target parts and the original hierarchy tree. Intermediate semantic changes cannot become safe by adding one more shrink. Historical assessment and candidate access checks both original and frozen-current authorization coordinates, including current target and evidence source.

For external obligations, `department_master.impact_external_owner_access` explicitly binds actor, external domain, campus, WRITE/REVIEW permission, declared Owner role and accepted responsibility version. An ORG26 responsibility is not an implicit external grant. REVIEW also requires the authenticated human identity named by `ownerSignatory`; proposal and reviewer remain independent. Service consumers can only acknowledge their bound synthetic handoffs. Existing external records are retained, without retroactive authorization or a claim of real Owner implementation.

Q15 evidence is limited to Department evolution and explicit disposition of its supported references. A017 evidence is limited to this finite dependency observation, original snapshot preservation and synthetic handoff. Neither closes P2-08, the whole phase, or real downstream migration.

Formal policy adoption, FULL profiles, maintenance UI, actual restart, real integration and formal acceptance remain separate pending/not-run conclusions.
