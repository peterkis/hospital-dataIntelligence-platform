# P1-06 review repair: exact workbook manifest references

## Boundary

Private workbook drafts are authorization-bearing encrypted records. Dataset contracts, governance scopes and `manifestProtected` do not identify the exact objects carried by manifest rows. Current V3 metadata therefore includes a deterministic `manifestReferences` projection for every non-empty row target and each ORG03 platform subject/campus endpoint, including row, dataset, scope, intent and expected versions.

The projection is authenticated with the encrypted draft. Changing a target, endpoint, pair, version, scope or intent changes the metadata digest comparison. Alias-only create rows produce an authenticated empty reference set.

## Current authorization

Migration 0077 extends `workspace_authorize` after bundle-dimension checks:

- ORG01 and ORG02 targets require current object authorization in their actual scope.
- ORG03 relation targets must still exist in the recorded subject/campus pair.
- Each selected ORG03 platform endpoint requires current object read access.
- A complete ORG03 platform pair requires the requested read/review permission, or `ESTABLISH`/`REVISE` for writes according to the authenticated row intent.

The shared function governs list, read, capabilities, save, discard and submit. Old protected bundle metadata without the exact-reference projection fails closed. Existing rows, ciphertext and migration checksums are not rewritten.

## Verification

Fresh-database tests revoke exact ORG01 target access and ORG03 pair access, then verify list/read/resave/submit denial and recovery after restoring the same grant. The populated 0076→0077 test first reproduces raw encrypted-envelope disclosure under 0076, upgrades the same database, and confirms the same draft is rejected without data, ownership or ACL drift.
