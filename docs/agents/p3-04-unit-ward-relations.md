# P3-04 科室—病区关系

Authority: user-approved `.scratch/p3-04-unit-ward-relations/spec.md`; ADR0141.
Baseline ab6e8002fa2792dca52539b877fa144240fd2631; predecessor0185.

`care-organization` owns UnitWardRelation. Platform UUIDs are generated by the
database. Unit, Ward, physical Campus UUID, purpose and business start are fixed
anchors. Source 收治/共享 map to ADMISSION; 管理 maps to MANAGEMENT. Primary
uniqueness is Ward × purpose over half-open business intervals. A management
relation must follow the Ward Owner's approved manager throughout its interval.
Unit and Ward must be admitted for that entire interval at the same transaction
record time. NORTH/SOUTH is an authorization coordinate, distinct from Campus UUID.
Cross-campus input remains protected evidence and reports
CROSS_CAMPUS_POLICY_REQUIRED; no special policy is adopted in this ticket.

CREATE, REVISE and permanent END use protected input, independent human
verification, frozen candidate review, approval and atomic Apply. REVISE replaces
the complete declared interval. Expiry never falls back to an older open version.
END is permanent and can only confirm or shorten an existing end. Its separate
`endAt` clips the declaration; the source row retains that declaration's original
period and content. Current authority and protected materials still apply to END,
while upstream admission failure cannot prevent this non-expanding action.

Sharing has no percentage calculation. NO_SHARING_REQUIRED is independently
confirmed for a single admission Unit. SHARED_BOUNDARY pins an exact rule
reference/version, protected material, complete participant list and business
window. All overlapping admission declarations must agree on that rule and cover
every participating Unit. Existing histories and the final batch projection are
checked together. Adding an uncovered participant requires repair of affected
old declarations in the same revision. UNKNOWN remains review-required.
Independent verification compares staged and reviewed governed rules through
the same normalized time and participant set. Stored input and all14 source
fields retain their original evidence form and signed replay digests. Legacy
rules use the same semantic comparison; END retains the exact original approved
rule in its formal fact and earlier history. Participant order is retained in
protected staging/verification evidence; normalization sorts comparison copies.
An explicitly empty `sharing_rule` source string stays distinct from native null.
For an old accepted null-collapse, END verifies the authenticated original empty
source field and preserves its accepted formal content. Native-null source fields
cannot be changed to empty text during END.

## Atomicity, dependencies and recovery

Apply reuses CatalogTransactionScope and the existing coordinator. Lock901002,
database-issued transaction-bound R proof, approved immutable candidate, full
projected sharing constraints, audit, formal facts and durable outcome participate
in one root transaction. Restricted SQL independently checks original upstream
pins and current admission. Application roles have no direct Owner table DML.
A changed dependency invalidates the candidate as STALE_VALIDATION. A late-row
write/audit failure rolls back the entire revision. ACK loss recovers the exact
candidate/request outcome before any new evaluation; replay creates no new facts
and reconciliation requires MATCHED with current permissions.

Finite Department/Campus readers retain original accepted pins/digests while
reporting the newest declaration clipped by END. Future obligations disappear
after END; historical evidence remains. Evolution/lifecycle assessments include
UNIT_WARD_RELATION and require explicit unavailable-owner declarations when the
port is absent. Exact committed CREATE/END results feed the existing impact seam.
These readers do not implement patient, nursing, bed or allocation algorithms.
