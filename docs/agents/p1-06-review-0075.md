# P1-06: previous-draft authority and exact comparison / scope displays

This note extends ADR 0127 and the historical 0074 repair note. It does not claim persistent deployment, formal acceptance or production readiness.

## Previous and replacement draft authority

Migration 0075 replaces only the existing `workspace_save` function, preserving its OID, owner and ACL. It adds current READ and READ_RESTRICTED checks for `previous.metadata` before an existing draft can append a new revision. The old WRITE check and all three replacement-metadata checks remain. A tab retaining decrypted content cannot erase or retarget the old boundary to bypass its revoked read grants.

The patch is forward-only; 0071–0074, stored envelopes, historical digests and prior outcome records are not rewritten. An unknown function baseline fails rather than guessing. Restored authority permits the refused request to be retried normally. Idempotent response recovery does not append another draft revision or decrypt the old material.

The shared startup / deployment release boundary is now 0075. A persistent database at 0071–0074 cannot enable workspace routes until the complete ordered and checksummed release is installed. `reuseExisting` requires the complete release; it is not an upgrade shortcut. The previous 0073→0074 regression remains a historical compatibility test, not permission to run the current application on 0074.

The new real HTTP / PostgreSQL test covers old READ and READ_RESTRICTED revocation for ORG01, ORG02, relation and scope drafts, plus old creation-scope READ_RESTRICTED revocation for subject-only and campus-only drafts. The replacement remains independently accessible; refusal must preserve envelopes, versions, jobs, artifacts, inputs and request outcomes. Restoring the removed grant permits the same request and idempotent replay. Two authorized retargeting paths continue through independent approval and Apply.

The 0074→0075 mode first reproduces the previous implementation's successful retargeted resaves with retained material, then upgrades the same populated isolated database and repeats the negative and positive paths. Existing migration checksums, data-table digests, database identity and function OIDs/owners/ACLs are checked by the adapter.

## Comparison request ownership

The entity view delegates comparisons to a component with its own request generation. Every selector edit and every request invalidates older results; entity, actor, observation-window changes and unmount also invalidate the component. Results are labeled with the captured from/to pair. Late successes, late errors and thrown network failures cannot overwrite newer results or resurrect a cleared comparison. Comparisons do not advance the entity's request epoch or interfere with maintenance requests.

Real Chrome tests use actual generated clients, HTTP handlers and database-backed organization/campus diffs. Only one response is delayed or turned into an error; no React hooks or domain results are mocked. Both entity kinds cover late success, late error and selector edits without a second request.

## ORG03 bundle scope license visibility

Every scope card displays its stored full license ID, exact version and version ID independently of option loading. Batch ROW_LICENSE references are explicitly labeled as unresolved batch references and show their source subject alias rather than inventing a platform version. Incomplete references remain visible with a warning and the existing explicit scope removal action; rendering never rewrites them.

The platform-license picker is an addition editor, not the selection state of all existing scopes. Its pending radio selection remains visible until the user explicitly appends it. The new scope then has its own exact-reference card. Actor/subject changes reset pending additions, and read-only state prevents adding. Existing evidence, periods, services and original workbook bytes are preserved.

The browser regression restores a real encrypted workbook with two versions of one license, checks both exact cards and the remaining batch references, explicitly adds another scope, saves, and opens the saved revision again. This is an editing/restore regression; it does not imply approval of the draft or replace domain validation.

All CI results must be tied to the final commit's artifact. WSL/installed-key orchestration uses test doubles; SQL/HTTP/browser checks use disposable GitHub databases. User-owned persistent databases, production deployment and full-site manual acceptance are not performed by these review repairs.
