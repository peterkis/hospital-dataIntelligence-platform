# 医院数据治理平台 Demo 30 分钟讲解稿

演示对象全部来自 `HDI Demo Hospital` Synthetic Prototype。开场时先指出页面顶部常驻的“非生产环境”提示，避免把演示结果误解为生产、部署或安全结论。

## 0–4 分钟：为什么需要数据治理

打开“治理驾驶舱”。

讲解要点：医院的收费项目、价表和系统代码经常分散在多个系统里。真正的问题不是把这些表集中起来，而是回答五个问题：谁能改、改了什么、谁审核、何时生效、下游为什么得到这个结果。

指向驾驶舱的五项统计。说明本次只用 5 个收费项目和 3 套价表验证方法，不代表全院数据量。强调 PostgreSQL 保存的是版本、审批、发布、解析和审计事实，不是静态页面样例。

沿“采集 → 标准化 → 审核 → 发布 → 消费 → 追溯”逐项说明：治理闭环的终点不是发布按钮，而是消费结果可以回到当时的版本和规则证据。

## 4–8 分钟：展示主题域

切换到“主题域”。

讲解要点：医院 MDM 蓝图包含组织、人员、科室、收费项目、价表、审批流程和审计日志。本演示当前只把收费项目和价表作为可操作主题域；其余卡片明确标记“规划中”，避免把蓝图位置说成已经实现。

展开一个收费项目的“技术详情”。说明业务用户默认只看到名称、状态和治理含义；`objectId`、`versionId`、`digest` 保留给技术核验，默认关闭，不要求领导或业务专家输入 UUID。

指出每个收费项目同时有一个已发布版本和一个修订草稿。已发布内容保持不可变，后续修改形成新版本候选。

## 8–18 分钟：收费项目治理流程

切换到“治理流程”。左侧用五步概览定位：创建、提交、审核、发布、消费；右侧完成现有引导式操作。

1. 以“数据维护员”创建收费项目草稿。说明草稿尚不可消费。
2. 提交变更。系统自动带入稳定身份、版本和内容摘要，冻结待审内容。
3. 切换到“专业审核员”。说明提交人不能代替专业审核，界面切换只是 Synthetic Prototype 身份模拟，不是正式认证。
4. 切换到“终审负责人”。终审批准后由平台服务在治理流程中自动发布，不存在绕过审批的手工发布员。
5. 展开审批时间线，说明每步记录 actor、role、action 和 `Asia/Shanghai` 本地日期时间。

讲解时不输入 UUID、不调用 API、不查看日志。若需要核验，才展开技术详情查看对象标识、版本标识和 digest。

## 18–24 分钟：价格解析

回到驾驶舱的“规则可解释”区域，或继续治理流程中的价格解析步骤。

按页面顺序讲解：

```text
请求
  ↓
院区专用：未命中
  ↓
院区通用：未命中
  ↓
全院专用：未命中
  ↓
全院通用：命中
```

最终结果是单价 `12.34 CNY`、数量 `2`、金额 `24.68 CNY`。强调这不是前端按优先级猜出的价格；后端价格解析模块保存每一级候选和命中证据，前端只展示结果。

再对比三套价表：它们具有不同适用院区、业务生效时间和价格。院区差异价需要前置确认、专业审核和 Owner 终审，不能由院区自行覆盖全院默认价。

## 24–28 分钟：审计追溯

回到驾驶舱的 Audit Timeline。

选取创建、提交、专业审核、终审和发布事件，依次读出：时间、合成 actor、role 和 action。所有时间采用 `YYYY-MM-DD HH:mm:ss` 展示，语义固定为 `Asia/Shanghai`；没有 `Z`、UTC 或 offset。

展开一条审计事件的技术详情。说明审计事件有流内序号，时间戳用于展示，序号才是流内权威顺序。审计数据只追加，历史失败或已发布内容不会被 prepare 覆盖修复。

## 28–30 分钟：结论与边界

总结：当前演示已经证明收费项目—价表—审批—发布—解析—审计可以形成同一可运行纵向切片，并能用领导可读的驾驶舱解释治理价值。

最后明确未完成项：Keycloak 正式认证、多院区真实数据接入、HIS/厂商接口、生产部署、部署认证、安全认证和正式 ABG 都不属于本任务。下一步是否进入这些内容，需要单独授权、独立计划和正式证据。
