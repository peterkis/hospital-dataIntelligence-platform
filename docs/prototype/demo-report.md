# 医院数据治理平台 Demo 报告

PV-004 将现有收费项目—价表—价格解析—审计纵向切片整理为可直接讲解的“医院数据治理平台演示版”。演示环境固定使用 `HDI Demo Hospital`、两个合成院区和合成角色，不接触真实医院、人员或患者数据。

> 本成果是 Synthetic Prototype，不是正式生产系统、正式身份认证、正式 ABG、部署认证或安全认证。

## 启动方式

```powershell
npm run prototype:demo:prepare
npm run prototype:demo
```

浏览器访问 [http://127.0.0.1:3000/admin/](http://127.0.0.1:3000/admin/)。`Ctrl+C` 会关闭 Fastify 应用与数据库连接池，并释放 3000 端口。

`prototype:demo:prepare` 依次检查 PostgreSQL、应用 11 个版本化原生 SQL migration、确认基础 Prototype 合成身份、协调 Demo namespace、生成完整演示数据并执行完整性检查。它不会执行 `DROP DATABASE`；已发布演示历史保持不可变，只清理由 PV-004 namespace 产生且仍处于草稿状态的废弃对象。结果写入根目录的 `demo-ready-report.json`，输出不包含数据库密码或 `DATABASE_URL`。

## Demo 数据

- 1 个医院治理主体展示：`HDI Demo Hospital`；
- 2 个院区：总部院区、高新院区；
- 5 个收费项目，每个包含 1 个已发布版本、1 个修订草稿、完整审批记录和审计记录；
- 3 套已发布价表：门诊价格表、住院价格表、医保价格表；
- 8 个已发布领域版本：5 个收费项目版本与 3 个价表发布版本；
- 100 个 Demo namespace 审计事件；
- 1 条可解释价格解析：`12.34 × 2 = 24.68 CNY`，依次检查院区专用、院区通用、全院专用并命中全院通用。

重复执行 prepare 会协调到同一组业务对象，不创建重复收费项目、价表或价格解析。完整性检查同时确认 migration 清单未变化、合成身份边界成立、时间为 `Asia/Shanghai` 无时区本地日期时间。

## 已演示能力

- PostgreSQL 持久化；
- 收费项目与价表的数据治理流程；
- 数据管家、专业审核和 Owner 终审的职责分离；
- 审批后自动发布；
- 固定两级、通用/专用互斥的价格解析；
- 可解释的规则命中路径；
- 只追加审计和技术详情追溯；
- 驾驶舱与医院 MDM 主题域蓝图。
