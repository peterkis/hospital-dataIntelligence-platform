# 价表政策证据、院内价格主权与映射边界

状态：政策、院内价格、医保、外部映射及POC覆盖边界均已确认

更新日期：2026-07-31

## 1. 已确认边界

本项目将政策证据主权与院内价格主权分离。院内收费项目语义、价表和价格金额均由医院的唯一内容Owner在平台内维护、审批和发布：

1. 院内收费项目稳定身份由医院创建和治理。
2. 收费项目版本由医院维护名称、服务内涵、包含或除外内容、计价单位和约束。
3. 价表发布版本和价格条目由医院内部审批发布。
4. 外部政策资料可以留证和被引用，但不能直接创建、覆盖、停用或发布院内项目和价格。
5. 医院必须显式认定政策资料的适用性，政策发布方不取得院内价格发布权限。
6. 不将任何合成或院内价格冒称为国家、地方或医保正式价格。

## 2. 政策资料留证

`policy_source_evidence`用于保存外部政策、规范或指导文件的原始证据：

- 发布机构、文号或来源标识、标题、发布日期和可获得的生效信息。
- 来源地址、获取时间、原始文件、媒体类型、文件大小和数字摘要。
- 原文版本或修订关系、内容摘要及可定位的条款索引。
- 资料治理状态、导入批次、记录时间和只追加审计链。

政策来源资料是证据对象，不是价表发布版本、收费项目目录或价格黄金源。新资料不得覆盖旧资料；来源内容更正时保存新的证据版本并关联前一版本。

## 3. 政策适用认定

`policy_applicability`表达医院Owner对政策资料的院内解释：

- 目标可以是收费项目版本、价表发布版本或后续确认纳入的业务规则版本。
- 关系类型固定区分依据、参考、限制和解释；POC至少建立4条适用认定，具体目标基数由合成fixture声明。
- 记录适用范围、业务有效期、条款定位、解释结论、Owner、审批和发布信息。
- 发布时冻结目标对象版本和政策证据版本，不动态指向所谓“最新政策”。
- 政策证据修订、失效或解释改变只创建影响事项，由Owner显式确认延续、替换或结束认定。
- 适用认定与收费项目、价表分别发布，不做跨对象原子发布。

## 4. 外部系统代码映射的角色

HIS、财务、体检或历史系统等项目代码只用于系统间转换和历史数据解释：

- 外部系统代码不直接充当院内收费项目稳定ID。
- 外部系统名称、代码或计价单位不自动创建或修改院内项目。
- 外部代码命名空间独立治理系统、对象类型、院区范围、代码规则、Owner和生命周期。
- 外部代码拥有稳定身份和不可变版本，代码名称或语义变化不覆盖历史。
- 语义映射独立于收费项目和价格条目，允许多对多并明确等同、院内更窄、院内更宽或仅相关。
- 运行转换使用独立操作绑定，按用途、方向、院区范围和业务时点唯一命中一个院内目标。
- 需要一对多生成时操作绑定指向已发布映射规则或收费组套，不能依赖多条语义映射的顺序。
- 外部系统代码变化只能产生映射重审事项，不自动迁移院内收费项目或价格。
- 本阶段不接真实系统，映射使用合成命名空间与仿真消费者验证。

政策适用认定、外部代码语义映射和运行操作绑定必须分表、分权限、分版本：三者分别回答“外部资料怎样影响院内决策”“两个代码对象语义上怎样关联”和“指定用途下运行时应确定转换到什么”。

具体规则见[ADR-0062](../adr/0062-separate-semantic-mappings-from-operational-bindings.md)。

POC固定使用五个合成命名空间：`SIM_HIS_CHARGE`、`SIM_FINANCE_REVENUE`、`SIM_PHYSICAL_EXAM_ITEM`、`SIM_LEGACY_CHARGE`和`SIM_CAMPUS_LOCAL_CHARGE`，分别验证双向收费转换、财务单向分类、体检组套、历史时态和院区范围。决策见[ADR-0064](../adr/0064-five-synthetic-external-code-namespaces-for-price-poc.md)。

## 5. 决策演进

ADR-0053曾排除政策源文件证据。经对研究报告（5）重新讨论，现确认政策资料可以作为来源资料备份，但院内价格继续保持唯一内容主权。新边界由[ADR-0054](../adr/0054-separate-policy-evidence-from-internal-price-sovereignty.md)记录；ADR-0053保留为被取代的历史决策。

政策资料在POC中以至少2份来源资料和4条适用认定验证原文件留证、版本、审批、影响和审计；这些样本不代表官方完整清单，也不取得院内价格主权。

## 6. 医保目录与待遇边界

医保目录、待遇规则和患者结算不能并入价表主数据：

1. 医保目录项目拥有独立稳定身份、版本、来源证据和生命周期。
2. 院内收费项目与医保目录项目通过独立版本化多对多映射衔接，映射冻结双方版本并拥有自身Owner、审批、有效期和审计。
3. 支付资格、支付限制、报销比例、自付和封顶等进入独立医保待遇治理，不进入价格条目。
4. 患者医保资格、费用结算和报销结果是业务事实，不进入基础主数据。
5. 价格解析先确定唯一院内价格，待遇解析随后消费价格结果、目录映射和待遇规则；两次解析分别保存证据。
6. 医保身份和待遇结果不得反向改写收费项目、价表或价格金额。

该分域模型见[ADR-0055](../adr/0055-separate-price-master-from-insurance-benefit-governance.md)。POC范围已量化为8个医保目录项目、10条收费项目医保映射和4条代表性待遇规则，患者结算事实继续排除。
