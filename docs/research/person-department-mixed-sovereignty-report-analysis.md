## 2. 报告带来的有效增量

报告最有价值的新增判断不是表名或字段，而是以下四点：

1. 人员主数据不是员工宽表；人员身份、任用关系、任职关系、专业资质、来源标识和生命周期事件需要独立演进。
2. 人员与科室、院区、地点、服务、岗位和角色之间是带有效期的关系，不是人员主表上的一组当前字段。
3. 多院区治理需要统一稳定身份和通用规则，同时允许院区或专业Owner维护其职责范围内的局部事实。
4. 科室与人员共用稳定身份、版本、关系、映射、事件和审计的治理范式，但二者的生命周期和权威责任不能合并为一个通用组织人员大表。

## 3. 对既有项目边界的适配

报告默认多院区异构集团，本项目已经限定为一个医院治理主体，可包含内部多个院区。因此“混合主权”在本项目中必须解释为：

- 全院层统一签发人员和科室稳定ID，维护跨院区唯一性、共享规则、共享字典、发布框架和审计。
- 唯一组织与人员权威来源仍是身份和核心人事事实的唯一来源，不引入多个系统对同一属性竞争覆盖。
- 院区、医务、护理、人力资源等责任方按治理对象、属性类别和院区范围维护其职责内事实，并经过各自Owner审批。
- 院区可以提出或维护获授权的本地任职、本地映射和局部视图内容，但不能覆盖全院身份、全院条目或其他Owner的事实。
- 跨院区任职、人员主身份合并拆分、科室结构变更和共享字典变更由全院级Owner复核。

这是一种“统一身份主权＋分域事实主权＋集中发布审计”，不是多租户、多个黄金源或按来源优先级自动覆盖。

## 4. 报告建议与既有决策的取舍

| 报告建议 | 本项目处理 |
|---|---|
| 多医院集团与院区异构 | 收敛为一个医院治理主体内的多院区范围 |
| `employee_master`保存当前雇佣状态、归属院区等 | 不采纳宽表；状态和归属进入独立关系或版本对象 |
| 科室主表保存`home_campus_id`、`business_domain` | 不视为永不变化属性；院区、业务性质按版本或关系治理 |
| 科室身份允许`REAL/VIRTUAL/GROUP` | 不采纳；已确认分组节点只存在于单个层级视图，不取得科室稳定ID |
| 科室版本直接保存诊疗科目和病案代码 | 不采纳；诊疗科目使用独立版本化映射，病案口径进入独立视图或映射 |
| 科室版本直接保存负责人ID | 不采纳；负责人应是人员对科室的有时效任职角色 |
| 已发布拼写修正可按SCD1覆盖 | 不采纳；草稿可修改，已发布内容任何更正均形成新版本或补偿发布 |
| 吸收合并可保留承接方科室ID | 不采纳；已确认实质合并的所有后继科室使用新稳定ID |
| 组织变化时自动迁移权限 | 不采纳自动迁移；只生成影响事项，由权限域显式确认 |
| 对接HR、HIS、排班、IAM等真实系统 | 排除；本阶段只使用合成权威源和仿真消费者 |

## 5. 人员主数据候选对象图

以下是报告适配后的候选边界，仍需逐项确认：

| 候选对象 | 核心含义 | 不应放入 |
|---|---|---|
| 人员主体 | 一个自然人的全院稳定身份及最小识别信息 | 当前科室、岗位、在离职状态、权限 |
| 人员标识 | 全院人员号、权威源ID、院区旧工号等有来源和有效期的标识 | 用标识替代人员稳定ID |
| 任用关系 | 人员与医院之间的员工、合同、派遣、进修、访问或其他正式工作关系 | 具体科室岗位、排班、薪酬明细 |
| 任职关系 | 人员在指定科室、院区以及可选地点或服务中承担某种岗位/角色的有效期关系 | 人员主体属性、系统权限 |
| 专业资质 | 分层表达资质定义、个人实例、适用范围、只追加核验和任职资质要求 | 实际任职、访问权限、覆盖式核验状态 |
| 岗位与角色参考数据 | 岗位类别、任职角色、职称、专业等可版本化代码和允许值 | 具体人员任职事实 |
| 人员来源映射 | 权威源或历史系统人员键到人员稳定ID的映射 | 人员合并的无审计覆盖 |
| 人员生命周期事件 | 入院任用、关系结束、复职、借调、兼职、资质到期等变化依据 | 当前态宽表 |

系统账号、OIDC身份、业务访问权限、薪酬、考勤和排班事实继续处于人员主数据边界之外。平台可以发布人员和任职变化供这些域使用，但不得把它们反向塞入人员主数据。

## 6. 已确认的混合主权责任矩阵

| 对象或事实 | 权威/审批建议 | 院区或专业维护边界 |
|---|---|---|
| 人员稳定身份与身份消歧 | 全院人员Owner；唯一权威来源供数 | 院区只能提交疑似重复和更正申请 |
| 法定姓名及核心身份属性 | 唯一权威来源；全院人员Owner审批 | 不允许院区覆盖 |
| 任用关系 | 人力资源Owner | 院区可提交本地事实，不可覆盖正式关系 |
| 院区内任职关系 | 对应院区或专业Owner | 仅维护授权院区和对象 |
| 跨院区任职或主归属任职调整 | 全院人员Owner或其指定Owner复核 | 院区提出申请并共同确认 |
| 医师资格与执业注册 | 医务管理Owner | 院区上传证据和发起核验，不得自行批准 |
| 护士资格与执业注册 | 护理管理Owner | 院区上传证据和发起核验，不得自行批准 |
| 进修、规培和实习证明 | 教学管理Owner | 院区或带教单位提交材料 |
| 科室稳定身份 | 全院组织Owner | 院区只能提出新增或变更 |
| 行政、运营、病案视图 | 各视图独立Owner | 在视图和院区授权范围内维护 |
| 岗位、角色、职称、专业代码 | 每个字典或值域独立Owner | 不因人员域权限获得全部字典权限 |
| IAM账号与业务权限 | IAM/安全域 | 只消费人员与任职发布，不属于人员主数据 |

跨院区变更采用来源院区与目标院区前置确认、单一全院领域Owner最终审批。院区确认不形成并列所有权；任一必需确认缺失或拒绝时当前治理对象不得发布，但其他独立治理对象不回滚。提交人与最终审批人必须不同，审批后由平台服务执行发布。决策记录见[ADR-0049](../adr/0049-centralize-identity-and-distribute-professional-fact-ownership.md)。

## 7. 建议的POC验证重点

- 同一人员跨院区拥有主归属任职和兼职任职，不复制人员主体。
- 任用关系结束后人员稳定ID保留，再次任用不重新制造人员身份。
- 人员改名只改变人员版本，不改变任用、任职和历史事实的身份引用。
- 科室拆分或合并只产生任职影响事项，不自动迁移人员。
- 专业资质到期阻断依赖资质的未来任职就绪，但不删除人员主体或历史任职。
- 当前主归属任职的唯一性按明确用途、作用域和业务时间校验，而不是全局硬编码。
- 权威来源初值、院区提案、专业Owner核验、全院发布和审计链均可回溯。
- 人员、任职、资质、岗位字典和值域分别独立审批与发布，不做跨对象原子发布。

## 8. 下一步决策顺序

已确认人员主体覆盖所有具有正式医院职责的自然人，不限于正式员工；一个自然人只保留一个全院人员稳定ID，离院、返聘、再次任用或转换用工形式不重建身份；患者身份与人员身份分域治理，不自动合并。决策记录见[ADR-0044](../adr/0044-include-all-formally-engaged-hospital-personnel.md)。

已确认任用关系分为劳动或人事、派遣或服务、外部专业、培训或学习四个一级类别，每项关系具有独立ID和版本；连续续聘沿用关系ID，结束后再次任用或关系基础改变时新建关系ID；多项关系按版本化重叠规则受控并存，治理状态、业务状态与人员主体状态分离。决策记录见[ADR-0045](../adr/0045-model-engagements-as-independent-overlap-governed-relations.md)。

已确认任职关系隶属于一项任用关系，任职安置与有期限的任职角色独立建模；组织作用域、任职用途和任职方式显式区分，主归属唯一性按用途、作用域和业务时间校验，调动、兼职、借调和轮转分别留痕。科室负责人不进入科室版本。决策记录见[ADR-0046](../adr/0046-separate-assignment-placement-from-timed-roles.md)。

已确认专业资质按资质定义、个人实例、适用范围、只追加核验记录和任职资质要求分层治理，并由医务、护理或教学Owner按类别审核。缺失、未核验、到期、撤销或范围不匹配只阻断依赖它的临床任职和消费；历史与无关用途保留。POC覆盖医师资格、医师执业注册和护士执业注册。决策记录见[ADR-0047](../adr/0047-govern-credentials-in-layers-and-block-by-dependency.md)。

已确认人员域POC建设任用一级类别、任用二级类型、任职用途、任职方式、岗位类别、任职角色、专业技术职称、专业代码和资质类型九组代码系统，并建设六组上下文值域。状态机和核验状态由平台固定，重叠、唯一性、角色占用及资质要求作为版本化规则，不得伪装成字典或值域。决策记录见[ADR-0048](../adr/0048-limit-personnel-poc-to-nine-code-systems-and-six-value-sets.md)。

已确认全院人员身份集中主权、专业事实分域主权和院区范围维护。跨院区兼职、借调、轮转或主归属调动需要来源与目标院区前置确认，再由唯一全院领域Owner终审；多专业Owner不构成多个人员黄金源。决策记录见[ADR-0049](../adr/0049-centralize-identity-and-distribute-professional-fact-ownership.md)。

已确认人员域使用24名合成人员，建立不少于30项人员标识及来源映射、32项任用、42项任职、36项任职角色和18项资质实例，关联2个院区及不少于12个合成科室；执行不少于36个强制场景，REST API全部覆盖，管理界面至少覆盖12个端到端场景。决策记录见[ADR-0050](../adr/0050-validate-personnel-poc-with-24-synthetic-people.md)。

人员域报告适配及边界确认已经完成，可进入详细数据模型、接口和测试计划。
